# @mxlang/preact

## 0.1.0-alpha.38 — 2026-11-17

- **Changed (attr-tag-prototype):** Every value host (html, Preact, React, Hono, Solid) now passes a callee Marko's attribute-tag record for `<@name>`: the first occurrence's attributes plus `content`, with every later occurrence reachable through iteration and through `map`, `filter`, `length`, `at` and `toArray` on its prototype. The value no longer depends on the callee's `Input`: repeated, conditional and looped occurrences fold into one record in source order, nested attribute tags are records, a bodiless occurrence has no `content`, and a dynamic tag given a record renders its `content` (nothing of its own for a bodiless one, as in Marko). The helper is core's `ATTR_TAG_RUNTIME`, inlined once per module that uses it. `AttrTag<T>` now takes the occurrence's attributes (`AttrTag<{ label: string }>`, `AttrTag<{ content: (row: Row) => … }>`) and is assignable to `Marko.AttrTag<T>`; the `{ as, attrs, params }` config form, `AttrTagProp` and `HostDeclarations.attrTags` are deprecated and read by nothing. The diagnostics that came from reading the callee's `Input` (missing or repeated attribute tags, undeclared tags, params mismatches, unreadable callees) are gone; a typed callee's `AttrTag` props are checked by TypeScript in `mx-tsc` and the editor plugin, at the attribute, or at the tag name for a missing attribute and for a repeated or conditional tag. Astro and Angular project from `attributeTagTree`. Solid's own components (`<Show>`, `<Switch>`, `<For>`, `<Repeat>`, `<Loading>`, `<Errored>`) still take a lone, attribute-free `<@fallback>` as its `content`; any other library component given `<@fallback>` receives the record, so pass `fallback=` instead.
- **Fixed (call-tag-var-shadows-define):** A tag call's `/var` (`<Make/T/>`) now hides a `<define>` of the same name in its body and the bodies nested in it, so `<T/>` there calls that value as a dynamic tag, as stock Marko does, instead of the outer `<define>`. html rendered the define there without `/var`, and with `/var` bound the define's value. Preact, React and Hono refused a `/var` on that call; they now bind it, and a `/var` on any dynamic tag whose value is a `<define>` that declares `<return>` now binds that define's value instead of `undefined`.
- **Fixed (core-diagnostic-order):** When two diagnostics apply, the real error now wins. A host that declares `<script>` as an `error` row refuses the tag with that refusal alone, as an `unsupported` row does. A throwing compile reports a `<script>` placeholder, then the body's syntax error, before the head and attribute refusals, as stock Marko does. Under `structural: "reject"`, an `<if>` or `<for>` holding attribute tags inside a registered tag reports `MX_STRUCTURAL_CONSTRUCT` instead of `MX_INVALID_ATTRIBUTE_TAG`. `<try>` and `<return>` under a tag with a contract report `MX_NOT_IN_DATA_FILE` instead of `MX_TAG_NOT_ALLOWED`. A file whose `analyze` hooks fail on several tags reports each tag's error, with the earliest in the file as the primary one. `<html-script>`'s raw-text body is read as raw text on a host that registers no core taglib (the shared JSX hosts' whole-file compile). On the Preact, React and Hono hosts an `<html-script>` body is now one raw text: markup-looking text in it (an element in a string, an `<if>`, a comment) is kept as script text instead of being refused with "read as markup". An `<html-comment>` body is raw text there too.
- **Fixed (core-ir-additive):** Type parameters written on a `<define>` (`<define/Foo<T>|{ v }: { v: T }|>`) are kept on its function head instead of being dropped while the params kept their annotations, which left `T` undefined: html and Preact (React and Hono share the emitter) print `<T,>`, Solid prints `<T>`, and the new IR field `Define.typeParams` (`{ code, span }`) carries them. A type error inside a shorthand placeholder (`<div.a${y}.b/>`, `<div#a${y}/>`) is now reported at the placeholder's own column instead of one or two columns off: the new IR field `Expr.parts` gives each authored expression inside a shorthand value core built its span and printed range, and `mappedExpr` maps each one onto its own source. A statement's `end` (`Import`, `Static`, `Export`, `InputInterface`) now stops at the authored text, trailing spaces excluded. `IR_VERSION` is 10.
- **Fixed (define-body-attr-tags):** An attribute tag in a `<define>` body (`<define/Bar><@item x=1/></define>`) is no longer refused: as in Marko, each attribute-tag name is a property of the define's value, after its attributes (`${Bar.item.x}` reads `1`), evaluated where the `<define>` is written and outside its params; the rest of the body stays the define's content. Repeated, `<if>`/`<for>`-wrapped and bodied attribute tags fold into Marko's attribute-tag record on html, Preact, React, Hono and Solid. On Solid, a define with attribute tags reads them like its attributes, and a whole-value read of one that also has a body stays refused. On Angular, the record goes into the define's `@let` for attribute tags with attributes only, including under an `<if>`; a repeated, `<for>`-wrapped, bodied or nested attribute tag in a define body is a positioned `MX_UNSUPPORTED_CONSTRUCT` there. The IR `Define` gains an optional `attributeTagTree` (`IR_VERSION` 16), and `defineValueWrapper` takes the attribute-tag names as an optional second argument, so `<@name>`, `<@length>`, `<@caller>` and `<@arguments>` get the same writable wrapper an attribute of that name gets.
- **Added (define-return):** `<return>` inside a `<define>` body, as in Marko 6.4.4: `<define/Thing|input|><return=input.n * 2/><i>${input.n}</i></define><Thing/double n=21/>` binds `double` to `42` and renders `<i>21</i>`. core lowers the value onto `Define.returnValue` (`IR_VERSION` 15), applies the position and count rules per define, accepts `/var` on a call of a define that returns (`Component.returnsValue`) and refuses a `/var` that repeats the define's name as a duplicate declaration. html, Preact (and through it React and Hono) and Solid (in `.solid.mx` regions) bind the value on a `/var` call and render only the output everywhere else. Angular refuses the `<return>` at its value (`MX_UNSUPPORTED_CONSTRUCT`), as it refuses a page's or a tag's own.
- **Fixed (dialect-vocabulary):** A dialect's `messageVocabulary` now reaches the messages that ignored it. The parser's `tagShorthands: false` refusals (`#id`, a leading `.`) name an attribute in the dialect's noun, through a new optional `SyntaxTable.anAttribute` that core sets from the vocabulary. The html target's unresolved-tag and element attribute-tag messages, and every host's unresolved-tag message, use the file's voice (`formatTag`, the attribute noun); core exports `voiceOfCtx` for it. A shorthand class beside a `class` attribute is now `MX_MERGED_SHORTHAND_CLASS` (was `MX_DIALECT_HOOK_ERROR`), so a dialect's `diagnosticCodes` map can rename it, and its message no longer shows the `.a` token.
- **Fixed (file-kinds-deps):** File-kind suffix checks follow one rule, the lower-cased name ends with the suffix: `Counter.Solid.MX` and `Card.MX` are now the same file kind in the build, the Bun loader, the editor plugin, the language server and the Angular host (its `include` matching, watcher and output paths) as their lower-case names. For `.marko`, only the Vite plugin's import claiming and the discovered-tag lowering checks follow it; the `tags/<name>.marko` tag-file probe, the extensions a dialect claims and the default import that marks a tag import stay case-sensitive, so `import Card from "./Card.MX"` still lowers as a dynamic tag. A failed compile of a Preact/React/Hono region, an `.astro.mx` template or an `.ng.mx` file, and a Solid error thrown after lowering, now carries `dependencies` naming the callees it read (for a Solid/Preact/React/Hono region file, those of the regions accepted before the failing one too), so the editor and the language server re-check the caller when the callee changes; core exports `attachDependencies` and `errorDependencies` for this, and `AstroTemplateError` gains `dependencies`. tsconfig `paths` aliases now reach `.mx` callee imports in region files, `.astro.mx` and `.ng.mx` callers in the TypeScript plugin and `mx-tsc` (a new optional `resolveImport` on `HostRegionInput`, `RegionCompileOptions` and each host's region, Astro and Angular entry). `mx-tsc --astro` loads the project's own `@astrojs/language-server` before its bundled copy.
- **Fixed (followups-c-fixed):** On Preact, a `<define>` rendered through a dynamic tag's attribute form (`<${R} x=1/>`) no longer receives Preact's context object as its second param: it is `undefined`, as in Marko, and the argument form (`<${R}("p", "q")/>`) still passes every argument. React and Hono already behaved this way. A define's params are typed from their parser nodes instead of a text scan, so a string default with an escape (`a = "x\"y"`) and a leading-dot number default (`a = .5`) are kept as written, their type inferred, instead of being typed `any`.
- **Fixed (followups-d):** A repeated attribute tag (a fold of several occurrences, or one under `<if>`/`<for>`) is now type-checked at each occurrence's own attributes when the callee declares the prop: `mx-tsc` and the TypeScript plugin report a wrong attribute, such as `<@item id="x"/>` where `id` is a number, at that attribute instead of at the tag name. Core adds a contextually typed builder, `__mxAttrTagsOf` (`ATTR_TAG_BUILD`), to `ATTR_TAG_RUNTIME`, and the html, Preact, React, Hono and Solid emitters build such a record with it; a fold certain to add an occurrence (one outside any `<if>`/`<for>`, or one in every branch of an `<if>`/`<else>`) passes it `true`, so the record also satisfies a required prop; a fold no declared type reaches keeps `__mxAttrTags`. The runtime record is unchanged. Solid's generated loop names (`__mxRow0`, `__mxEntry1`, …) now come from a per-compile serial in the reserved `__mx` space instead of a scan of the authored names, so they no longer depend on what the template binds.
- **Fixed (hono-parity):** Hono, Preact and React match stock Marko in four rendering details. A `<@catch>` whose body is a `<for>` renders its rows without commas on Hono. `${1n}` prints `1` and `${0n}` prints nothing on Hono. A null-prototype object in a Hono text placeholder throws, as it does in Marko, instead of printing `[object Object]`. A spread's `textContent` and `innerText` keys are written as ordinary escaped attributes (`textcontent=`, `innertext=`) on Preact, React and Hono, so no renderer hyphenates them or assigns them as DOM properties.
- **Fixed (html-target-bugs):** The html target refuses `dangerouslySetInnerHTML` on a native element, as stock Marko and the other hosts do. `<html-style>` keeps its attributes and escapes its body for style context on the html target, and writes a real `<style>` on the Preact, React, Hono, Solid and Astro hosts instead of a literal `<html-style>` element. A `client` declaration no longer emits a `var` for a name the module already declares (`static function q(){}` beside `client export namespace q`, or two `client` statements naming one name). The region and unit entry points of the Preact, React, Hono, Solid, Astro and Angular hosts erase tag type arguments (`<p<string>>`) instead of refusing them.
- **Fixed (html-typecheck):** `IR_VERSION` goes from 8 to 9: `Const` gains an optional `varType` and `Text` an optional `check`. The html and preact type-check projection now reports errors it dropped: the annotation of `<const/c: string = n/>` and `<let/c: T = n/>` is kept; the initial value of `<const>`/`<let>`, `<let valueChange=…>` and the default value of an inert tag (`<id=x/>`, `<log=x/>`) are evaluated and mapped to their authored text; an angle assertion (`<T>x`) inside an expression is printed `(x as T)` so tsc no longer reads it as a JSX tag (core, `stripTypes: false` only); and the html spread loop no longer raises TS2367 on generated code. The html target prints a `<for|x: number, i: number|>` head without the annotations (it was invalid JavaScript), and inlines the member reads of an unexported `const enum` (`${E.A}`, `${E["A"]}`) and drops its declaration, as stock Marko does. The `.astro.mx` attribute helper returns `any`, so `<p title=s/>` with `s: string` no longer reports a false TS2322 under `mx-tsc --astro`.
- **Changed (jsx-binding-names-changed):** `@mxlang/host-preact/emitter`: the fourth parameter of `createEmitter` and the fourth of `createRegionEmitter` take the set of names local to the body (`scopeLocals(new Set(), [], ir.body)` for a whole template). The `WeakSet` of calls `shadowedCalls(ir)` returns is still accepted there with its old meaning (a call in it keeps its authored name, every other define call reaches the private function) and is deprecated. `RegionSink.claimed` is folded into `root`, and `scopeLocals` is exported. `paramNames` and `shadowedCalls` are deprecated: they remain, built on core's binding analysis, for callers of this subpath.
- **Fixed (jsx-binding-names-fixed):** On Preact, React and Hono a tag param that rebinds a `<define>`'s name makes a call to it inside that body a call to the param whatever the param list holds: a regex or template-literal default (`|{ a = /[}]/, Row }|`) no longer hides the names after it, and the emitter reads the names from the IR in place of scanning the param text. The public `const Row = __mxDefine(…)` is now kept or dropped by a parse of the emitted module, so a `\u` escape in the module no longer keeps every one. On Solid, a plain `/var` that repeats the name of a `/var` in another body of the same component (`<counter/x/><div><counter/x/>${x}</div>${x}`) now compiles with a binding of its own, so each body reads its own value, as in Marko; before it was refused. A destructured `/var` repeating such a name, and an assignment to a repeated `/var`, are still positioned compile errors. On Angular and Solid, a read of a `<let>` or other accessor-backed name that a tag param rebinds (a tag body's `|n|`, a `<define>`'s destructured param, a dynamic tag's or `<@catch>`'s params, an attribute-tag `<for>`'s params) is no longer rewritten to the outer accessor (`n()`); it reads the param.
- **Fixed (jsx-define):** JSX-host fixes on `<define>` bodies and module typing. A `.mx` component whose `Input` types `content` as a function no longer fails `tsc` with TS2322 in its own file. A `/var` inside a whole-file `<define>` body is declared inside that body (it was dropped, and two defines referenced an undeclared temp). A `/var` inside a dynamic-tag body or a `<try>` `@placeholder`/`@catch` body is scoped to that body, so it can sit beside an outer `/x` as in Marko. A `<define>` used as a dynamic target (`<const/R = Row/>` then `<${R}>`) now receives the body as `content`. An untyped `<define>` param is typed `any` so a `noImplicitAny` project reports no TS7006. A region now refuses a `<define>` inside a dynamic-tag or `<try>` body, which it used to lift out of the body's scope, and a `/var` in the `<try>` main body is body-scoped like `@placeholder` and `@catch`. A `<define>` called directly from MX (`<Row(x)/>`) receives its arguments untouched; only the define's value, which a dynamic tag reaches, reads a `children` body as `content`. The body of an imported value tag (`<Box>…</Box>` over an `import`) is its own `/var` scope too, so its `/x` can sit beside an outer `/x` and runs when the component renders its children. The wrapped public define value (and its helper) is emitted only when something reads it as a value, so a define that is only called directly no longer leaves an unused binding under `noUnusedLocals`. The body of a direct `<define>` call is a `/var` scope too. A define that is read only by `<return>` or by a prelude statement keeps its public binding, a define with attributes that is only called directly no longer leaves an unused one, and a define param defaulting to `null` or `undefined` is typed `any`. A define read through a spread (`...Row`) keeps its public binding. A region lifts a `<define>` out of an imported tag's or a `<define>` call's body unless the body declares a `/var`, and a lifted define's name is unique across every scope of the region. The typeCheck projection calls a define through its public name. A direct call of a define whose name a param also binds (a `<for>` or define param) calls the authored name, so it reaches the local. A define with a non-ASCII name keeps its public binding. An untyped define param is typed `any`, except a plain name with a primitive default (`n = 1`), which keeps the type TypeScript infers from it. A region refuses a define lifted out of a tag body that declares tag params, and a region `/var` clashes by name with a define lifted from a tag body (`Duplicate declaration`). A param default holding a regex or template literal makes the call route by the authored name instead of dropping a shadowing binding. A `.preact.mx`/`.react.mx` region compiled for the TypeScript plugin projects defines by their public names, as the whole-file projection does, so a hover and `noUnusedLocals` never name `__mxDef_<name>`. The public define keeps its `length` as well as its `name`. `HostRegionInput.typeCheck` (core) and `RegionCompileOptions.typeCheck` (targets) are a new tooling-only option: the TypeScript plugin sets it so a region is projected the way a whole file is, with a direct define call typed and mapped by the define's own name while the private function still runs, so an argument arrives as written. A param default holding a comment, regex or template literal fails safe to the authored name.
- **Fixed (jsx-hosts-2):** An outer custom-tag `/x`, dynamic-tag `/x` or `<const/x>` read after a dynamic-tag or `<try>` body that declares its own `/x` now compiles and reads the outer binding, as in Marko; an outer `<let/x>` read after such a body is still refused, and a body `/x` with no outer binding is still not in scope after the body. On Solid, which keeps one binding per name for a component's `/var`s, a `/var` that reuses an earlier `/var`'s name in the same component is now a positioned compile error instead of sharing that binding. On Preact, React and Hono, a `<try>` body under `<@placeholder>` that binds a `/var` runs its statements inside a component below `Suspense`, so a `/var` call that suspends shows the placeholder (with `<@catch>` too). A dynamic tag with tag arguments and a body emits the body once instead of twice. A module or region with a dynamic tag declares only the dynamic helpers it calls, so `__mxDynamicPair` no longer ships without a dynamic `/var`. The refusal of markup in an `<html-script>`/`<html-style>` body names the file's tag rules instead of "this host". On Solid's server render, an `oncapture:click` attribute (static, dynamic or a spread key) is printed (as `Oncapture:click`, which an HTML parser reads as `oncapture:click`) instead of dropped.
- **Fixed (jsx-mappings):** A `.preact.mx`, `.react.mx` or `.hono.mx` region compile now returns the emitter's recorded `mappings` (`CompileJsxRegionResult.mappings`, generated offsets into `code`, source offsets file-absolute), so the parser bridge places a define's name, a direct call and a later read of a rewritten or repeated name without searching the emitted text; the emitted `code` is unchanged. On the JSX hosts a `$!{value}` sole child, a structured `class=[…]` beside a spread or passed to a called unit, a spread entry's attribute name, `<if>`/`<else-if>` conditions, `<for>` `of`/`in`/`from`/`to`/`step`, a function-form `by=` and attribute-tag `<if>`/`<for>` values are mapped to their authored text; on the html target `<if>`/`<else-if>` conditions and the `<for>` and attribute-tag loop sources are. In the type-check projection, a host-component call bound to an import with no attribute tags (`import { Card as C } from "./barrel"` then `<C title=1/>`) is written as the JSX element it renders, so a wrong prop is reported at the attribute as it is through a direct `.mx` import; build output is unchanged. The parser bridge keeps the location of a name a host recorded inside a type the host generated (`typeof Row` in `(__mxDef_Row as typeof Row)(1)`), so rename and find-references from a define's direct call in a region reach the define and its other reads; such a type with no recorded mapping is still detached. Because recorded mappings place JSX tag and attribute names at their authored lines, a printed JSX region module's line layout can differ; its code is unchanged.
- **Fixed (jsx-misc):** A lone sequence placeholder (`<if=c>${0, x}</if>`) as the only child of a branch compiles to valid TSX on React. A `NaN` `class`, `className` or `style` is omitted, as stock Marko omits it, instead of printing `class="NaN"`. A method shorthand in a dynamic tag's props or an attribute-tag attribute maps its head and body exactly. `<html-script>` with an event handler (`onclick() {}`, `onClick=fn`) is refused on the JSX hosts, as it is on the html target. In `.<host>.mx` regions, a type error in a generic constraint of a method shorthand's head (`onClick<T extends Missing>(e: T) {}`) is reported at the authored span. On Preact and React, a `<try>` whose body threw directly stays on `<@catch>` when the input changes and the body no longer throws, as Marko does; it used to re-render the body.
- **Fixed (marko-parity):** `<log/>` and concise `log` with no value are now refused with "The `<log>` tag requires a `value=` attribute." (`MX_INVALID_ATTRIBUTE`) at the tag name, as Marko refuses them, on the html target and on every host that lowers `<log>` through core's built-in branch; `<log=1/>`, `<log value=1/>` and `<debug/>` still compile. The inert `Disposition` gains an optional `value?: "required"` for this. A named tag that core lowers as a dynamic tag (a value import such as `import Foo from "./foo.js"`, or a local whose value it cannot prove is a function) now refuses arguments beside a plain attribute (`<Foo(a) x=1/>`: "Tag does not support arguments when attributes or body present.", at the arguments) instead of compiling with the attribute dropped; arguments beside a body still compile. An authored dynamic tag over a namespace import's member (`import * as J from "hono/jsx"` then `<${J.Fragment}>…</>`) now carries the new optional IR field `importMember` on its dynamic target (`IR_VERSION` goes from 10 to 11), and the JSX hosts pass its body as hand-written JSX would, so on Hono a lone `0` renders nothing, as `<J.Fragment>{0}</J.Fragment>` does.
- **Changed (neutral-names-other-hosts):** Messages a template author can see on Solid, Angular, Astro and the html target no longer name MX or Marko. A `client` block "holds code that runs only in the browser" (Solid, Angular); Solid's `<html-comment>` refusal "cannot render <!--…-->"; the `on:` fix-it says "`on:click=fn` is not an event binding" on Angular, Astro and html, and Solid's "was removed in Solid 2" drops "(Marko rejects this form too)"; `:=` "is a two-way binding" (Solid, Angular); Angular's `class:`/`style:` modifier "is not supported in an Angular template" and its `<const>` pattern-key refusal drops "as in Marko"; Astro's directive-named attribute "cannot be preserved as a plain attribute"; html's `<await>` refusal drops the sentence about Marko and its strict `<script>` refusal reads "`<script>` runs client code and requires a runtime". The run-time errors of the dynamic-tag helper that Preact, React and Hono print into their output, and Solid's own copy, drop the "MX: " prefix ("tag params |…| cannot be passed to a native element: …", "this value is a data attribute tag …"). The marker on a TypeScript diagnostic in generated code, in mx-tsc and the tsserver plugin, now reads " (in generated code, not yours: an internal bug; generated L:C)". Error codes, positions and severities are unchanged.
- **Changed (neutral-names-parser-preact):** Messages a template author can see no longer name MX or Marko. The parser's `MX_FRONT_END_INTERNAL` messages now read "The front end failed while building the syntax tree (not yours: an internal bug): …" and "The template parser threw instead of reporting an error (not yours: an internal bug): …". The Preact emitter, which React and Hono share, rewords four refusals: a `client` block "holds code that runs only in the browser"; `<html-comment>` "cannot render <!--…-->"; the `on:` fix-it says "`on:click=fn` is not Preact syntax" (React, Hono: their own dialect name) without "(Marko rejects this form too)"; and `:=` "is a two-way binding". Error codes, positions and severities are unchanged.
- **Changed (preact-names):** The loop bindings the JSX emitter names itself are `__mxList<n>` (the copied `<for of>` list), `__mxValue<n>` (an omitted `<for in>` value), `__mxIndex<n>` (a range loop's counter) and `__mxAttrIndex<n>` (an attribute-tag `<for>`'s index), numbered by one serial per compile. They were picked by scanning the authored and emitted text for identifiers, so an authored name could change them (`<const/value=1/>` before `<for|k| in=input.o>${value}</for>` emitted `([k, value2])`). Rendering is unchanged. `@mxlang/host-react` and `@mxlang/host-hono` compile through this emitter and emit the same names.
- **Changed (tag-var-callback-scope):** A `/var` inside a `<for>` body, an `<if>`/`<else-if>`/`<else>` branch, an attribute-tag body or a call's content now binds in that body's own scope, as in Marko 6.4.4 and the html target, instead of failing with "`/var` on `<X>` inside `<for>`/`<if>` is not supported … yet". It binds once per row or rendered branch, reads the row's own bindings, and can sit beside an outer `/var` of the same name. On Preact, and on React and Hono, which compile through the Preact emitter, the body's statements run in a function called in place; a `.preact.mx`/`.react.mx`/`.hono.mx` region accepts it too, including in a region `<define>` body. On Solid, a `<For>` row, a `<Show>`/`<Match>` branch, a call's content and a `<define>` body declare their own `let` for the binding.

## 0.1.0-alpha.37 — 2026-11-09

- **Changed (host-dispatch-d3):** The TypeScript plugin's mapping pass now looks tags up through the compile target's own translator instead of always html's: `createHtmlMappings` gained a public optional trailing `translator` parameter, `compileMxVirtual` passes the target descriptor's, and a target that defines none falls back to the default target's. The `preact-jsx`, `react-jsx` and `hono-jsx` target descriptors declare a lazy memoized `translator`; the registry's `defaultTag` scope and contract checks also resolve those targets' own translator now (equivalent tables, mappings unchanged for every existing target).

- **Fixed (satisfies-typecheck):** An authored `x satisfies T` (and `x as T`, `x!`) in a template placeholder is no longer erased from the type-check module: `@mxlang/target-html`'s tooling projection (`typeCheck: true`) now keeps the TypeScript wrappers so tsc checks them, and `@mxlang/host-astro` forwards the tooling flag to it, so a failing `satisfies` reports at its authored position instead of silently passing. Expression, argument and pattern containers holding an angle-bracket cast (`<T>x`) still undergo the full type strip, including surrounding wrappers and chained casts: the tooling projection is checked as TSX, where a kept `<T>` parses as a JSX tag and breaks the whole file. This also removes angle-cast prefixes from the shared Preact/React/Hono type-check output. Tag type-argument and type-parameter containers (`<const<string>/x=…/>`, `<p<string>>`, `<Foo<string> …/>`) are still dropped in this mode, so tags accepted by the html build remain accepted by its tooling projection. The shared Preact/React/Hono type-check output now accepts them too, where it previously rejected them with `MX_UNSUPPORTED_CONSTRUCT`. Runtime output is unchanged; the wrappers are still stripped for builds.

- **Fixed (solid-method-head-map):** Method-shorthand parameter types, defaults and generic constraints on ordinary element and component attributes in whole-file Solid, Preact, React and Hono templates now report TypeScript errors at their exact authored positions. Solid also covers dynamic-tag props and attribute-tag attributes. Printed method heads are mapped separately from their bodies; emitted code is unchanged.

## 0.1.0-alpha.36 — 2026-10-19

- **Fixed (attribute-args-refusal):** React, Preact, Hono, Solid and Angular reject attribute argument lists such as `onClick(v)=fn` at the attribute where Marko refuses them, instead of silently dropping the arguments. `<define>` and `<const>` retain Marko's acceptance and dropped arguments; builtin, host-tag and region module-statement errors keep their existing precedence. Write `onClick=fn` instead; method shorthand remains subject to the host's existing callable-value policy. Hosts opt in through the generic `attributeArgs: "refuse"` declaration; core's default IR lowering still retains attribute arguments, including dialect expressions.

## 0.1.0-alpha.35 — 2026-10-19

- **Fixed (jsx-duplicate-lifted-binding):** Whole-file JSX templates now reject collisions among `<const>`, lifted `<define>` and static or dynamic `/var` bindings, rather than emitting duplicate `const` declarations. Earlier markup errors remain visible before top-level duplicate checks, and separate define-body and parameter scopes remain legal. A top-level `<define>` is unchanged and is visible in every later body. A placeholder in an expression position (a ternary arm, a render-prop arrow body) is unchanged.

The `<const>`, `<for>`, `<define>` and `<let>`-position rules apply on every target, so a template that wrote one of these now fails on Preact, React, Hono, Solid, Angular and Astro too (for example `<const/x=1/>` with `<button onClick() { x = 2 }/>` compiled to `onClick={function () { x = 2; }}` on Preact, React and Hono before). - **Changed (script-body-syntax-check):** A `<script>` body that does not parse is now a compile error, `MX_INVALID_STATEMENT`, positioned at the syntax error, as in Marko. A decorator, JSX, a proposal syntax, an `assert { … }` import attribute (write `with`) or a CommonJS `import x = require(…)` / `export = value` in a `<script>` body is refused with a message that says what to write instead (a `.ts` module for a decorated class, a tag for markup); a concise-mode body of several lines is read as one body, at positions in the file; any other error carries Babel's message at Babel's position. A body that parses compiles as before: an `import`, an `export`, a top-level `return` or `await`, type annotations, `enum`, `satisfies`, `namespace` and `declare` are accepted, and a body that holds a `${…}` placeholder is still not read. On a host that refuses `<script>` (Preact, React, Hono, Solid, Angular, Astro), a body that does not parse is now reported at its syntax error before the host's "`<script>` is not supported" message.

- **Fixed (html-script-target-support):** `<html-script>` now writes a real `<script>` element on every host, with its attributes and a body that is script text, as stock Marko 6.4.4 does. The html target (`@mxlang/target-html`) dropped every attribute (`<html-script type="module" src="/a.js">` printed a bare `<script>`) and HTML-escaped the body, so `a && b` reached the browser as `a &amp;&amp; b`; it now keeps the attributes (spreads, dynamic values and `nonce=` included, with the shared element rules) and writes the body as Marko does: each `${…}` stringified as in any text, then the joined body escaped for script context (`<script`, `</script` in any case and `<!--` become `\u003C…`), so no value can close the element. Preact, React, Hono and Solid printed a literal `<html-script>` element: they now print `<script>`, with the body through the renderer's raw-HTML prop (`dangerouslySetInnerHTML`, Solid's `innerHTML`) because a JSX renderer HTML-escapes a text child. Astro printed a literal `<html-script>` too: it now prints `<script is:inline … set:html={…}>`, `is:inline` so Astro keeps the element where it is instead of bundling it. Angular's template compiler removes every `<script>` element, so that host now refuses `<html-script>` at the tag with the ways Angular loads a script (`index.html`, the `scripts` array of `angular.json`, the DOM API) instead of emitting an element ngtsc rejects. - **Fixed (jsx-spread-raw-html-prop):** A spread object can no longer inject raw HTML into an element. The spread helpers now validate those keys like any other attribute and write them as lowercase attributes (`dangerouslysetinnerhtml`, `innerhtml`, `outerhtml`), which no renderer reads as a raw-HTML prop, so the output is the escaped attribute Marko prints and an HTML parser reads the same attribute name. An object value of one of these keys (`{ __html }`) now throws "cannot be a plain object", like every other attribute (Marko prints `[object Object]`). A literal `dangerouslySetInnerHTML=` on a native element or `<html-script>` is now refused at compile time with Marko's message ("`dangerouslySetInnerHTML` is not a valid attribute, did you mean `$!{html}`?"), at the attribute; a component target still receives it as a prop, and `$!{…}` is unchanged. On Solid, a literal `innerHTML=` on a native element or `<html-script>` is refused the same way ("`innerHTML` is not a valid attribute, did you mean `$!{html}`?"), because it is Solid's raw-HTML prop and so wrote raw markup where Marko prints an escaped attribute; a sole `$!{html}` child is the way to write raw HTML, and the "wrap it" hints in the Solid errors for `$!{…}` in a body with tag params now suggest `<div>$!{item}</div>` instead of `<div innerHTML=item/>`. A component target keeps `innerHTML` as an ordinary prop. On Preact, React and Hono a literal `innerHTML=` or `outerHTML=` on a native or custom element is now the same escaped lowercase attribute (`innerhtml`, `outerhtml`) instead of a property write, which wrote markup on a Preact client render. On Solid the spread view also closes the other routes to markup: a spread `outerHTML`, `textContent` and `innerText` are escaped lowercase attributes, `prop:innerHTML` and `prop:outerHTML` are dropped, an object `children` is dropped (the server renderer read `{ t: "<b>" }` as an already-rendered node), and on `<script>` and `<style>` (also a dynamic tag that resolves to one, in any letter case) `children` and the `prop:` text props are dropped too; a literal `prop:innerHTML=` or `prop:outerHTML=` on a native element is a compile error like `innerHTML=`, a literal `textContent=`, `innerText=`, `children=` or `prop:` text prop on `<html-script>` or `<style>` is a compile error, a literal `children=` on any other native element goes through the same view (an object is dropped), and a literal markup prop on a dynamic string tag goes through the view too. The error for an object value of a raw-HTML key now ends with "To write raw HTML, make `$!{html}` the element's only child."

- **Fixed (jsx-dynamic-tag-data-object-element):** A dynamic tag whose value is data no longer hands that data to the renderer as a node. `<${input.x}/>`, `<${input.x}(args)/>` and a template that is only `${input.x}`, with `input.x` set to a plain object from outside the template (JSON from a request, say) now render nothing, as in Marko 6.4.4; `<${input.x}>body</>` still renders `body`, as Marko does. On Hono the browser used to read `{ tag: "img", props: { onerror: "…" } }` as a real `<img onerror>`; on Preact's server renderer an object with a null prototype was read as a vnode the same way; on React a plain object threw. A copy of such data whose prototype was set from a `__proto__` key (`Object.assign({}, JSON.parse(…))`) is data too. A string still gives an element, a component is still called, and what the renderer built (a `hono/jsx` or `hono/jsx/dom` element, a portal, a Preact vnode, a React element) and arrays of them pass through. The check is chosen per host by a new optional `nodeShape` field on the shared emitter's dialect. Preact and Hono tell their own nodes apart by an own `constructor: undefined` and an own `key`/`ref`, which JSON cannot carry; data decoded by a library that keeps `undefined` (`devalue`, `superjson`, `structuredClone`) can imitate one and must not be used as a dynamic tag. Solid's server renderer still writes a `{ t: "<b>x</b>" }` object as markup; that waits on the runtime. The same copy, which used to pass Hono's text-placeholder guard as a class instance and render as an element in the browser, now prints as `[object Object]` there too.

- **Fixed (object-child-text-guard):** On Hono, `${expr}` holding a plain object from outside the template (JSON from a request, say) is now printed as text, `[object Object]` like Marko 6.4.4, instead of being read as an element by `hono/jsx/dom`: a `{ tag: "img", props: { onerror: "…" } }` object used to render a real `<img>` with its event handler and `dangerouslySetInnerHTML` in the browser. This covers a placeholder in a body and also one that is alone in an `<if>`/`<else>` branch, a `<for>` body, a component or render-prop body, `<@catch>` or `<@placeholder>`. An own `toString()` or `valueOf()` is honoured and the result is escaped. What Hono built is left alone: `hono/jsx` elements, nodes from the `hono/jsx/dom` runtime (`jsx`, `createElement`, `cloneElement`, `Fragment`), portals, strings, numbers and arrays of them, and a state update still re-renders the text. The dom runtime's plain node objects are told apart by an own `key` and `ref` that JSON cannot carry; data decoded by a library that keeps `undefined` (`devalue`, `superjson`, `structuredClone`) can imitate one and must not reach a text placeholder. The shared JSX emitter in `@mxlang/host-preact` gained an internal `textObjectGuard` dialect flag that only Hono sets, so Preact, React and Solid output is unchanged. Preact still renders nothing for a plain object in a text placeholder and React still throws, neither reading it as markup; the Preact, React and Hono host pages say so. On Solid's server renderer, a `{ t: "<b>x</b>" }` object in a text placeholder is still written as markup, the same as in hand-written Solid, because the runtime's rendered nodes are unmarked objects of that shape; the Solid host page tells authors to pass only strings, numbers or nodes, and the fix is waiting on the runtime.

- **Fixed (preact-ssr-text-null-proto-vnode):** On Preact, a `${expr}` placeholder whose value is data from outside the template can no longer be read as markup by the server renderer. `<p>${input.x}</p>` with `input.x` set to a null-prototype object that has the fields of a vnode (`type`, `props`, `key`, `ref`; a decoder such as `qs` with `plainObjects` builds these) used to render `<p><img src="x" onerror="alert(1)"></p>` on the server, while the browser rendered `<p></p>`, so hydration disagreed with the server HTML; the same went for an array holding one, and for a placeholder that is the only child of an `<if>`, a `<for>` row or a body. Such data now renders nothing on the server, as it already did in the browser, and a plain object still renders nothing, as before. Strings, numbers, vnodes (`h()`, the jsx runtime, `Fragment`, `cloneElement`, a component's return value), class instances and arrays of them are unchanged. Each non-literal placeholder is now passed through the `__mxRenderable` check the dynamic tag already uses, so the generated code gains that call and one hoisted helper. A vnode is told apart by its own `constructor: undefined`, which JSON cannot carry; data decoded by a library that keeps `undefined` (`devalue`, `superjson`, `structuredClone`) can imitate one and must not reach a text placeholder. The shared emitter gained an internal `textDataGuard` dialect flag that only Preact sets, so apart from the two data guards below, only generated helper text differs. An object whose prototype is an array (JSON can build one through a `__proto__` key and `Object.assign`) no longer passes the class-instance check of the shared `__mxRenderable` and `__mxTextValue` helpers: on a React, Preact or Hono dynamic tag it used to reach the renderer as a node (Preact hydration crashed), and in a Hono text placeholder it used to reach `hono/jsx/dom` as a node and render an element in the browser; it is now dropped, or printed as Marko prints it.
