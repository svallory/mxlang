# Upstream: `marko-js/tree-sitter`

This package is MX's own tree-sitter grammar for `.mx` files: a vendored
snapshot of Marko's grammar plus local patches. Decision 72 had `.mx` ride
Marko's grammar unmodified; decision 146 (`:name` sugar, and `#id`/`.class`/
`:name` in attribute position, `apps/docs/docs/design-notes/adr-name-sugar.md`)
made MX syntax a superset of Marko's, so MX owns its grammar from 0.2.0 of the
Zed extension on (decision 72 addendum, see `packages/editors/zed/UPSTREAM.md`).

## Local modifications

`patches/0001-feat-grammar-parse-id-class-and-name-shorthands-anywhere.patch`
is the branch commit `3e05834` (`git format-patch`), limited to the
hand-written files (its `src/parser.c`, `src/grammar.json`,
`src/node-types.json`, `package.json`, `package-lock.json`,
`tree-sitter.json` and `CHANGELOG.md` hunks are left out; the generated files
are regenerated here instead). It adds:

- **Scanner** (`src/scanner.c`): a `:` not followed by `=` starts a shorthand
  in the tag-name section. Attribute-position `#`/`.`/`:` start a shorthand
  after whitespace, `,` or `[` (`#` then a word character or `-`; `.`/`:` then
  an identifier start). An attribute value ends at whitespace followed by
  `.ident`, or by `:ident` when no conditional `?` is open
  (`ExprState.cond_depth`, which does not count `??` or `?.`). A value on the
  sugar (`:x=1`, `#x=1`, `.x=1`) is an error. The new state is serialized.
- **Grammar** (`grammar.js`): the `shorthand_name` node. Attribute-position
  shorthands use their own external start tokens and are aliased to the same
  three node names; tag-adjacent shorthands carry a `shorthand` field.
- **Queries**: `shorthand_name` is `@label`; the `<style>` dialect injection
  matches the `shorthand:` field only, so `<style .scss>` (attribute position)
  stays CSS and `<style.scss>` becomes SCSS.
- **Tests**: `__tests__/mx-shorthand.test.mts` (45 cases), and the
  fixture-event harness mapping attribute-position shorthands to htmljs's
  `attrName` events.

`patches/0002-feat-grammar-name-the-grammar-mx-and-run-the-tests-on-bun.patch`
is MX's own:

- The grammar is named `mx`: `grammar.js` `name`, the
  `tree_sitter_mx_external_scanner_*` symbols in `src/scanner.c`, and
  `tree-sitter.json` (`source.mx`, file type `mx`, version 0.1.0, no
  bindings). Zed looks up the `tree_sitter_<grammar key>` export, so
  `[grammars.mx]` needs this name, and it keeps the grammar from colliding
  with the `marko` grammar of Marko's own Zed extension when both are
  installed.
- The tests load the grammar through `web-tree-sitter` from
  `tree-sitter-mx.wasm` (`__tests__/util/language.mts`) instead of upstream's
  native `tree-sitter` binding, which needs node-gyp and a per-platform addon.
  `*.test.mts` became `*.bun-test.mts`: the root vitest run globs
  `packages/editors/*` and would otherwise collect them.
- `__tests__/util/htmljs.mts` pins htmljs-parser to v5.12.0
  (`16f453a6d86502c24578c339d17bc5ba81257539`, tagged the same day as
  `@marko/tree-sitter` 0.2.0) instead of degitting its unpinned HEAD. Against
  HEAD (5.18.0) upstream's suite has 53 failures at its own pin; against
  v5.12.0 it has none.
- `__tests__/fixtures.bun-test.mts` removes three `x .y` snippets from two
  fixtures before comparing: decision 146 splits `x .y` into a value and a
  class shorthand, where htmljs-parser reads one member expression
  (ADR 146, divergence 4). The test asserts each snippet is present, so a
  fixture change fails instead of silently comparing less.

`patches/0003-fix-grammar-start-binding-captures-around-their-text.patch`
is MX's own:

- `src/scanner.c`: the tag-param pattern, type and default, the tag-var type
  and the type-arg expression tokens used to include the whitespace before
  them, so a highlight capture on `<for|x: number, i|>` covered `" number"` and
  `" i"`. `es_skip_leading_ws` skips it as trivia before the token starts (as
  the scanner already did for attribute values). The tag-var type keeps the
  char before the whitespace as its lookbehind, so `a: (B | C)` still scans
  the way htmljs-parser does (fixture `tag-var-type-with-parens`).
- `src/scanner.c`: those tokens also end at their last non-whitespace char
  (`ExprState`'s automark skips whitespace under `trim_ws`); the separators
  (`,` `:` `=` `|`, and `>` of type args) skip the whitespace before them as
  trivia.
- `queries/highlights.scm`: `=` and `:=` of an attribute are `@operator`, the
  value `@none` (it is injected TS, like `param_default`).

## Tests

`bun run test` (`scripts/test.sh`, also `moon run tree-sitter-mx:test` and
the root `bun run test:grammar`):

1. `tree-sitter generate`, then `git diff --exit-code -- src/`.
2. `bun run build:wasm` (tree-sitter-cli 0.26.9 fetches its own wasi-sdk).
3. `bun test` over `__tests__/mx-shorthand.bun-test.mts` (45) and
   `__tests__/fixtures.bun-test.mts` (374 htmljs-parser fixtures plus one
   consistency check). The fixtures are fetched with git into `.cache/` once.
4. `tools/check-wasm.mts`: the wasm parses a sample, and both queries load.
5. `scripts/zed-compile-check.sh`: compiles `src/` from a clean clone of
   HEAD, as Zed's `file://` dev install does (CI: the `zed-compile-check` job,
   forced `tree-sitter build --wasm --docker` fallback with tree-sitter-cli
   0.24.7; see `../tree-sitter-solid/UPSTREAM.md` "tree-sitter-cli version
   split").

`bun run vendor:check` (`scripts/vendor-check.sh`) re-fetches the pin from
GitHub, applies `patches/`, and diffs the result against the committed files.
`.github/workflows/upstream-check.yml` runs it on every PR touching this
package; it is not part of `test` because it needs the network.

## Bump procedure

1. Grammar change on top of the current state: edit the files here, then
   capture the edit as a new `patches/000N-*.patch` (build upstream + the
   existing patches in a scratch repository, copy the edited files over,
   commit, `git format-patch -1`). Never rewrite an existing patch to add a
   hunk (`../tree-sitter-solid/UPSTREAM.md`, "A third defect").
2. New upstream pin: update `PIN_SHA` in `scripts/vendor-check.sh` and the
   table above, rebuild the patches against it, bump `HTMLJS_REV` in
   `__tests__/util/htmljs.mts` to the htmljs-parser release the new grammar
   was tested against, and re-check `MX_DIVERGENCES`.
3. `bun run generate`, `bun run test`, `bun run vendor:check`.
4. Commit, then move `rev` in `packages/editors/zed/extension.toml`'s
   `[grammars.mx]` to that commit (Zed only sees committed code).
