A dialect passed as the `dialect` option (to `compileSource`, `lowerSource`, a host or a fragment) is now checked for disjoint marks like one routed from its project. When the file name is absolute and its nearest `package.json` is found, the option is compared with the dialects that project installs, and a clash is one `MX_INVALID_DIALECT_MODULE` error at the start of the file that names both dialects, both rows and the shared mark, and says to change one row or remove one dependency; before, only a routed dialect was compared, so a build that passed its dialect directly could pass where the editor reported the clash. An installed dialect with the option's `id` is the option itself and is not compared with it. A relative or virtual file name, or a file with no `package.json`, names no project, so nothing is compared. A row marked with text core reads itself in the attribute list, a spread (`...`) or a tag's parameters (`|`), was accepted and never fired; it is now refused in a dialect module and in the option alike, as one `MX_INVALID_DIALECT_MODULE` error that names the row, its mark and the text core reads. The option's clash message says "the `dialect` option … and the installed dialect …", and to remove the dependency on the installed one. The comparison runs once per project for an unchanged (deep-frozen) option.
