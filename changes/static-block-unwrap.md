A `static { ... }` block now hoists its statements to module scope with the braces removed, as in Marko: `static { let q = 1 }` declares `q` for the whole module, so the template can read `${q}`, where the braces used to make `q` block-scoped and the read undeclared. Only a body that is exactly one block unwraps (`static { a } { b }` and `static { a };` keep their blocks, one level only: `static {{ a }}` hoists `{ a }`), an empty block (or one holding only comments) hoists nothing but is still a module statement, so a host or region with no module scope refuses it like any other `static`, and a comment after the closing brace is dropped with it. The statements inside keep their text, comments and positions, so an error inside the block still points at its line and column. `server { ... }` hoists the same way on the html target. The render-only name check reads the same block, so a template read of a block binding is fine, and `static { const count = 1 }` beside `<let/count>` is still refused at the declaration. The non-block `static x = 1` form is unchanged. `@mxlang/core` also exports `unwrapStatementBlock`, the one reading of the block form, for hosts that hoist a statement of their own.
