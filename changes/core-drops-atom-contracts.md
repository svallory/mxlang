packages: [core]
kind: Removed

**Breaking:** `@mxlang/core` no longer checks atom contracts. The `values`, `pattern`, `ref` and `declares` contract keys leave core's vocabulary: they are keys a syntax module may claim through `contractFields` and check in its own `checkContract` and `afterLower`, like any key core does not know. An attribute declaration that uses `values`, `pattern` or `ref` without a claiming module now gets the unknown-key error, and so does a tag that declares `declares` (``<tag>`: `declares` is not allowed: no syntax module claims it``), whether it comes from `customTags`, a sidecar or `mx.contracts`. Before, core checked `declares` itself. Removed exports: `atomCandidates`, `AtomCandidate`, `AtomFacts` and `ContractDeclaration`. Also removed: `CompileResult.atomFacts`, `TranslateError.atomFacts`, and the test-only `fallbackSyntaxForTesting` global. Kept, as `@unstable` data a claiming module reads and core never checks: the `values`, `pattern` and `ref` fields of `CustomTagAttribute` and `CustomTag.declares` (typed so a module's own contract files still type-check). Kept: `Atom` and `Member` values, `ContractAtomOrMember` (the whole-value kind a module builds, `@unstable`), the `type: "atom"` and `type: "member"` shape check, `ctx.declare`, `contractFields`, `checkContract`, `describeAttribute`, `afterLower` and `LoweredUnit`. The core wording for an enum on an atom slot lost its `; use `values`` suffix: a module gives the hint through `describeAttribute`. Built-in `=:x` atoms still lower as before.
