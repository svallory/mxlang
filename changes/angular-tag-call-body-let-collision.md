A `<const>` or `<define>` written in the body of an MX tag call (`<Card><const/a=2/>${a}</Card>`) or of an attribute tag (`<@header><const/a=2/>${a}</@header>`) is scoped to that body again on Angular. The body is projected content, but it is written in the caller's template, so its `@let a` shared the caller's view: beside an outer `<const/a=1/>` (or a sibling tag call declaring `a`) every read got the first value, and two `<define/D>` raised Angular's duplicate-declaration error. The emitter now gives such a declaration a name of its own only when its name collides, the same rule as for a native element body, and a body nobody else shares a name with is emitted exactly as before. No view is opened, so content projection into a hand-written component called by selector, named slots included, is unchanged. `@mxlang/angular-checker` prints the authored name in Angular's diagnostics for a renamed declaration in these bodies, as it does for an element body; `ng build` on the files `mx-angular build` wrote still prints the generated name for a collision. The built package no longer drops the collision count when it is built with Bun 1.3.14 (its TypeScript transpiler erased every `declare(…)` call statement as an ambient declaration, so each declaration in an element body looked like a collision and was renamed).
