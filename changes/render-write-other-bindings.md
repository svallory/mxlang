Writing a binding the template does not write is now a compile error, as it is in Marko, with three new codes. Each message gives the rule and the fix and sits on the assignment or update with its end (a `for...of` or `for...in` on the loop's left side). `MX_READONLY_BINDING_WRITE`: a `<const>` and a `<for>` parameter (value, index and key) are never written, whether the write is while the template renders, in an event handler or callback, or in a `<script>` body; a `<define>` parameter bound as a plain name (`|a|`) is refused the same way; a name bound through an object pattern (`<const/{ a }=…/>`, `<for|{ a }|…>`, `<define/D|{ a }|>`) is written through its object, so it is refused only while the template renders. `MX_LET_WRITE_BEFORE_DECLARATION`: a `<let>` is written only below its declaration, in a placeholder, a handler or a `<script>` body alike, counting a `<let>` later in the same block or after it in an enclosing one. `MX_LET_LOOP_ASSIGNMENT`: a `for...of` or `for...in` cannot assign to a `<let>`, also inside a handler. A parameter or local of the same spelling still shadows the binding. The `<const>`, `<for>`, `<define>` and `<let>`-position rules apply on every target, so a template that wrote one of these now fails on Preact, React, Hono, Solid, Angular and Astro too (for example `<const/x=1/>` with `<button onClick() { x = 2 }/>` compiled to `onClick={function () { x = 2; }}` on Preact, React and Hono before). A target that refuses `<let>` itself still reports a `<let>` written above its declaration first, as `MX_LET_WRITE_BEFORE_DECLARATION`. The render write of a `<let>` (`MX_LET_WRITE_IN_RENDER`) is unchanged and stays on the html default policy. Solid now reports a write to a `<for>` parameter with the core message, so its "computed from its bounds" wording for a stepped range is no longer shown for a render write; its own refusals remain for what core does not reach. Not covered: a `<let>` or `<const>` written from a sibling block or above its declaration (for `<const>`), a name bound through an array pattern, the parameters of other tags, and a `<script>` body that does not parse. Before, all of these compiled without a message.
