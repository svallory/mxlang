Writing a binding the template does not write is now a compile error on the html default policy, as it is in Marko. Three new codes, each with the rule and the fix in the message and positioned at the assignment or update with its end (a `for...of` or `for...in` at the loop's left side). `MX_READONLY_BINDING_WRITE`: a `<const>` and a `<for>` parameter (value, index and key) are never written, while the template renders, in an event handler, in a callback or in a `<script>` body; a `<define>` parameter is not written while the template renders (an event handler or a `<script>` body still writes it, and so does a name bound through an object pattern, which writes through its object). `MX_LET_WRITE_BEFORE_DECLARATION`: a `<let>` is written only below its declaration, in a placeholder, a handler or a `<script>` body alike, counting a `<let>` later in the same block or after it in an enclosing one. `MX_LET_LOOP_ASSIGNMENT`: a `for...of` or `for...in` cannot assign to a `<let>`, also inside a handler. A parameter or local of the same spelling still shadows the binding. Not covered: a `<let>` declared in a sibling block, a name bound through an array pattern, the parameters of other tags, and a `<script>` body that does not parse. Before, all of these compiled without a message and a runtime took the write silently or failed at runtime. Hosts and the html `strict` policy refuse `<let>` and never reach the new `<let>` checks.
