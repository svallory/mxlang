A built-in `<script>` written with arguments (`<script(x)>`), params (`<script|x|>`), a tag variable (`<script/x>`), a second value (`<script value=a value=b>`) or a value next to a body (`<script value=a>code()</script>`) is now a compile error, as in Marko. Before, MX compiled all five and dropped the arguments, params and variable, and ignored the body or the second value, so the code the author wrote never ran or never ran as written. Arguments and params report Marko's "Tag does not support arguments." and "Tag does not support parameters." at the first argument or param, a tag variable reports that `<script>` does not support one, all three as `MX_INERT_TAG_SHAPE` with the tag spelled as the dialect spells it and the native `<html-script>` element named as the fix; a second value and a value next to a body report "Invalid duplicate value attribute." as `MX_DUPLICATE_VALUE_ATTRIBUTE`, at the second value or at the tag. One of them is reported per tag, in the order Marko checks them, so an attribute written before a second value is reported instead of it. Empty `()` and `||`, a value alone, a body alone, and a value next to a blank body or a body of only a `'use strict'` directive still compile. A second value that is bound (`value:=b`) is the duplicate, not an unsupported attribute. A `#id.class` shorthand is now reported at `#id`, the one written first, not at `.class`.
