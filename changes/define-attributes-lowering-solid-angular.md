A `<define>` with attributes (`<define/D a=1/>`, `${D.a}`) compiles on Solid and Angular and renders what Marko 6.4.4 does, where both used to refuse it. Static, dynamic and boolean attributes and a spread become properties of `D`, evaluated once where the define is written, with any number of defines, a define with params, a define that reads its own attributes in its body (Angular), and a define inside a `<for>` or an `<if>` (Angular). On Solid the siblings after the define read the attributes through a memoized `<Show>` (literal attributes read as `D.<attribute>` are inlined; a whole-value read of `D` takes the `<Show>` path so `D` keeps one identity), so they stay reactive and are evaluated once; on Angular the attributes are a `@let` beside the template reference. A define that has attributes and a body can only be read as `D.<attribute>` on both: `D.content` and any other whole-value use of `D` (`D`, `(D).content`, `D[key]`, `<${D}/>`) is a positioned error at the read, as is a bound attribute (`a:=x`). On Solid a define inside a `<for>`/`<if>` body, and a define whose body reads another define's dynamic attribute or its own attribute, stay refused (every define is hoisted there).
