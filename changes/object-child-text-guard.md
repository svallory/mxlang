On Hono, `${expr}` holding a plain object from outside the template (JSON from a request, say) is now printed as text, `[object Object]` like Marko 6.4.4, instead of being read as an element by `hono/jsx/dom`: a `{ tag: "img", props: { onerror: "…" } }` object used to render a real `<img>` with its event handler and `dangerouslySetInnerHTML` in the browser. This covers a placeholder in a body and also one that is alone in an `<if>`/`<else>` branch, a `<for>` body, a component or render-prop body, `<@catch>` or `<@placeholder>`. An own `toString()` or `valueOf()` is honoured and the result is escaped. What Hono built is left alone: `hono/jsx` elements, nodes from the `hono/jsx/dom` runtime (`jsx`, `createElement`, `cloneElement`, `Fragment`), portals, strings, numbers and arrays of them, and a state update still re-renders the text. The dom runtime's plain node objects are told apart by an own `key` and `ref` that JSON cannot carry; data decoded by a library that keeps `undefined` (`devalue`, `superjson`, `structuredClone`) can imitate one and must not reach a text placeholder. The shared JSX emitter in `@mxlang/host-preact` gained an internal `textObjectGuard` dialect flag that only Hono sets, so Preact, React and Solid output is unchanged. Preact still renders nothing for a plain object in a text placeholder and React still throws, neither reading it as markup; the Preact, React and Hono host pages say so. On Solid's server renderer, a `{ t: "<b>x</b>" }` object in a text placeholder is still written as markup, the same as in hand-written Solid, because the runtime's rendered nodes are unmarked objects of that shape; the Solid host page tells authors to pass only strings, numbers or nodes, and the fix is waiting on the runtime.
