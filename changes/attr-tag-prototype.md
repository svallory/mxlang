packages: [core, html, preact, react, hono, solid, astro, angular, tsx-bridge, typescript-plugin]
kind: Changed
---

Every value host (html, Preact, React, Hono, Solid) now passes a callee Marko's attribute-tag record for `<@name>`: the first occurrence's attributes plus `content`, with every later occurrence reachable through iteration and through `map`, `filter`, `length`, `at` and `toArray` on its prototype. The value no longer depends on the callee's `Input`: repeated, conditional and looped occurrences fold into one record in source order, nested attribute tags are records, a bodiless occurrence has no `content`, and a dynamic tag given a record renders its `content` (nothing of its own for a bodiless one, as in Marko). The helper is core's `ATTR_TAG_RUNTIME`, inlined once per module that uses it. `AttrTag<T>` now takes the occurrence's attributes (`AttrTag<{ label: string }>`, `AttrTag<{ content: (row: Row) => … }>`) and is assignable to `Marko.AttrTag<T>`; the `{ as, attrs, params }` config form, `AttrTagProp` and `HostDeclarations.attrTags` are deprecated and read by nothing. The diagnostics that came from reading the callee's `Input` (missing or repeated attribute tags, undeclared tags, params mismatches, unreadable callees) are gone; a typed callee's `AttrTag` props are checked by TypeScript in `mx-tsc` and the editor plugin, at the attribute, or at the tag name for a missing attribute and for a repeated or conditional tag. Astro and Angular project from `attributeTagTree`. Solid's own components (`<Show>`, `<Switch>`, `<For>`, `<Repeat>`, `<Loading>`, `<Errored>`) still take a lone, attribute-free `<@fallback>` as its `content`; any other library component given `<@fallback>` receives the record, so pass `fallback=` instead.
