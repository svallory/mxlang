A dialect can rename the codes core reports on its files with `Dialect.diagnosticCodes`, an explicit map from a core code (`MX_UNKNOWN_TAG`) to the dialect's own (`KIT_UNKNOWN_TAG`). `lowerSource` applies it once to its final diagnostics, and `checkDialectFile` applies it to the project scan's diagnostics (reserved tag names, misplaced or dotted tag files, ignored sidecars, `mx.tags` problems), so the language server, the TypeScript plugin and `mx-tsc` report one name per code. `@mxlang/core` exports `diagnosticCodesOf(filename)` (`@unstable`) for a tool that reports core diagnostics of its own. Only the code changes. A code the map does not name keeps its `MX_` code, a dialect's own `ctx.fail` code is never renamed, and `MX_INTERNAL_ERROR` and `MX_DIALECT_HOOK_ERROR` cannot be keys. An `MX_DIALECT_ERROR` entry loads and is ignored. A map that is not an object, names a key that is not a core code, or has a value that is empty or starts with `MX_`, fails the dialect at load.
