packages: [preact, react, hono, solid]
kind: Fixed

A spread object can no longer inject raw HTML into an element. On Preact, React and Hono, `<div ...input.attrs/>` with `attrs = { dangerouslySetInnerHTML: { __html: "<b>x</b>" } }` (or an `innerHTML` / `outerHTML` string) wrote that markup into the page, and Solid did the same for a spread `innerHTML`; stock Marko 6.4.4 prints these keys as ordinary escaped attributes. The spread helpers now validate those keys like any other attribute and write them as lowercase attributes (`dangerouslysetinnerhtml`, `innerhtml`, `outerhtml`), which no renderer reads as a raw-HTML prop, so the output is the escaped attribute Marko prints and an HTML parser reads the same attribute name. An object value of one of these keys (`{ __html }`) now throws "cannot be a plain object", like every other attribute (Marko prints `[object Object]`). A literal `dangerouslySetInnerHTML=` on a native element or `<html-script>` is now refused at compile time with Marko's message ("`dangerouslySetInnerHTML` is not a valid attribute, did you mean `$!{html}`?"), at the attribute; a component target still receives it as a prop, and `$!{…}` is unchanged. Solid's literal `innerHTML=` attribute is unchanged: it is Solid's documented raw-HTML form.
