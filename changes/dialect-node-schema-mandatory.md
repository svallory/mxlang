---
packages: [core]
kind: Changed
---
Every dialect node type must declare a schema, a forward and a printer, and the dialects a project installs must have disjoint marks. This is breaking for dialect authors: a node type without a `schema` no longer loads.

- Changed: `NodeType` has a required `schema: NodeSchema` (a new exported type), `{ fields, slot }`. `fields` names every field `parse` returns besides `type` and `span`, each `"node"` (child nodes; exactly the names in `keys`), `"expression"` (a host expression: a parsed expression node or `null`) or `"data"`. `slot` is the non-empty list of positions the type fills, from `"expression"`, `"value"`, `"line"` and `"attribute"`. The printer is `print` and the forward is the `ctx.expression` result `lower` returns in expression position; neither has a new field. Core checks the three when the dialect loads (`MX_INVALID_DIALECT_MODULE`, naming the dialect, the node type and the missing piece, in the dialect's module or at the `dialect` option), including `print` and `lower` being functions.
- Added: core checks what a type produces against its schema, each failure one `MX_INVALID_DIALECT_MODULE` error at the node's text or span that names the dialect, the type and the fix. A row naming a type at a position outside its `slot` is refused at load. A `parse` result with a field `fields` does not declare, or an `"expression"` or `"node"` field of another shape, is refused where the node is written. A node lowered at a position outside its `slot` (one placed with `ctx.attribute` in value position), or carrying an undeclared field, is refused at its span. A forward that another node already stands for (a literal kept in a variable and returned by two nodes) is refused at the later node; `lower` returns a new object each call.
- Added: the dialects a project installs (its own `mx.dialect` declaration and its direct dependencies that declare one) have disjoint marks. A row's mark is the literal text its `match` starts with, else the characters of its `chars`; two marks of different dialects may not be equal or one a prefix of the other (`%` against `%.`), whatever the position. When a file's dialect loads, a clash is one error in that dialect's module at 1:0 naming both dialects, both rows and the shared mark, and saying to change one row or remove one dependency.
- Migration (Mesh): add `schema: { fields: { name: "data" }, slot: ["value"] }` to `mesh:Atom` (`AtomValue` in `packages/compiler/src/front-end/syntax/mesh.ts`: it has `keys: []`, `parse` returns `{ name }`, and the type is claimed by the value row and placed by `ctx.attribute`, so only the value slot). Mesh's marks (`:`, `&`, `%.`) are disjoint from every other dialect that does not mark them. Any other dialect: declare `schema` on each node type, listing every field its `parse` returns, and keep `keys` equal to the `"node"` fields.
