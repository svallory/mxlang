The messages that refuse a construct a data file cannot hold now start from the file: "Data files are static, so they do not evaluate `<if>`", "`<define>` is a render-time macro: data files are static, so they cannot expand it; inline the content at each use", and the same shape for `<return>`, a tag variable, a dynamic tag, a capitalized tag the file binds, and `<!doctype>` ("... means nothing in a data file; data files describe tags and data, not a page"). They no longer say "the data tree is static; this file's consumer does not evaluate ...", so a consumer that matched that text must match the new one (the codes, `MX_STRUCTURAL_CONSTRUCT` and `MX_NOT_IN_DATA_FILE`, are unchanged). `MessageVocabulary.file` (`@unstable`) is now a string, as before, or `{ one, many, article? }`: with a string the plural is the string plus "s" ("Kit file" gives "Kit files"), the object states an irregular plural and the indefinite article, and the plural is capitalised where a message starts with it. A malformed `file` object fails the dialect at load. `MessageVocabulary.tree` is still accepted and validated, but no message reads it any more; leave it out.
