File-kind suffix checks follow one rule, the lower-cased name ends with the suffix: `Counter.Solid.MX` and `Card.MX` are now the same file kind in the build, the Bun loader, the editor plugin, the language server and the Angular host (its `include` matching, watcher and output paths) as their lower-case names. For `.marko`, only the Vite plugin's import claiming and the lowering checks follow it; the `tags/<name>.marko` tag-file probe, the extensions a dialect claims and the default import that marks a tag import stay case-sensitive, so `import Card from "./Card.MX"` still lowers as a dynamic tag. A failed compile of a Preact/React/Hono region, an `.astro.mx` template or an `.ng.mx` file, and a Solid error thrown after lowering, now carries `dependencies` naming the callees it read (for a region file, those of the regions accepted before the failing one too), so a watcher can rebuild when the callee is fixed; core exports `attachDependencies` and `errorDependencies` for this, and `AstroTemplateError` gains `dependencies`. tsconfig `paths` aliases now reach `.mx` callee imports in region files, `.astro.mx` and `.ng.mx` callers in the TypeScript plugin and `mx-tsc` (a new optional `resolveImport` on `HostRegionInput`, `RegionCompileOptions` and each host's region, Astro and Angular entry). `mx-tsc --astro` loads the project's own `@astrojs/language-server` before its bundled copy.
