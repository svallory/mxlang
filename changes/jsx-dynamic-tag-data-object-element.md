A dynamic tag whose value is data no longer hands that data to the renderer as a node. `<${input.x}/>`, `<${input.x}(args)/>` and a template that is only `${input.x}`, with `input.x` set to a plain object from outside the template (JSON from a request, say) now render nothing, as in Marko 6.4.4; `<${input.x}>body</>` still renders `body`, as Marko does. On Hono the browser used to read `{ tag: "img", props: { onerror: "…" } }` as a real `<img onerror>`; on Preact's server renderer an object with a null prototype was read as a vnode the same way; on React a plain object threw. A copy of such data whose prototype was set from a `__proto__` key (`Object.assign({}, JSON.parse(…))`) is data too. A string still gives an element, a component is still called, and what the renderer built (a `hono/jsx` or `hono/jsx/dom` element, a portal, a Preact vnode, a React element) and arrays of them pass through. The check is chosen per host by a new optional `nodeShape` field on the shared emitter's dialect. Preact and Hono tell their own nodes apart by an own `constructor: undefined` and an own `key`/`ref`, which JSON cannot carry; data decoded by a library that keeps `undefined` (`devalue`, `superjson`, `structuredClone`) can imitate one and must not be used as a dynamic tag. Solid's server renderer still writes a `{ t: "<b>x</b>" }` object as markup; that waits on the runtime. The same copy, which used to pass Hono's text-placeholder guard as a class instance and render as an element in the browser, now prints as `[object Object]` there too.
