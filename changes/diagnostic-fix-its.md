A diagnostic can now say how to fix itself. `IrDiagnostic.fixes` (`@unstable`) is a list of fixes, each `{ title, edits }` where an edit is `{ offset, end, newText }`: UTF-16 offsets into the same text the diagnostic's `offset` indexes (the file named by `file` when the diagnostic is positioned in another file), `end` exclusive, edits within one fix never overlapping, so applying all the edits of one fix to the original source gives the fixed source. The types are exported as `IrDiagnosticFix` and `IrDiagnosticEdit`, and a compile error carries the same list as `TranslateError.fixes`. The `<effect>` error (`MX_RESERVED_EFFECT_TAG`) now offers one fix, "Rename to `<script>`", that renames the open tag and, when there is one, the close tag; a self-closing tag, a concise tag and a `</>` close have only the open name. A host's "not supported" error for `<effect>` and the strict html policy's own row offer no fix. `fixes` travels wherever a diagnostic's `code` and `end` already do: the tag-file and tag-template errors, a JSX-region error re-raised by `@mxlang/tsx-bridge` (a non-enumerable `fixes`, offsets in the whole file), `AstroTemplateError`, `DialectDiagnostic` from `@mxlang/targets/dialect-check`, and the TypeScript plugin's `MxCompileDiagnostic`. The language server puts a diagnostic's fixes in its `data.fixes` and offers each one as a quick fix (code action) that edits the document, only while the text is the one the diagnostic was computed from. A fix for a diagnostic raised inside another file (a tag template) is not offered across files. The TypeScript plugin's tsserver diagnostics and `mx-tsc` do not show fixes.
