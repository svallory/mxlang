JSX-host fixes on `<define>` bodies and module typing. A `.mx` component whose `Input` types `content` as a function no longer fails `tsc` with TS2322 in its own file. A `/var` inside a whole-file `<define>` body is declared inside that body (it was dropped, and two defines referenced an undeclared temp). A `/var` inside a dynamic-tag body or a `<try>` `@placeholder`/`@catch` body is scoped to that body, so it can sit beside an outer `/x` as in Marko. A `<define>` used as a dynamic target (`<const/R = Row/>` then `<${R}>`) now receives the body as `content`. An untyped `<define>` param is typed `any` so a `noImplicitAny` project reports no TS7006. A region now refuses a `<define>` inside a dynamic-tag or `<try>` body, which it used to lift out of the body's scope, and a `/var` in the `<try>` main body is body-scoped like `@placeholder` and `@catch`. A `<define>` called directly from MX (`<Row(x)/>`) receives its arguments untouched; only the define's value, which a dynamic tag reaches, reads a `children` body as `content`. The body of an imported value tag (`<Box>…</Box>` over an `import`) is its own `/var` scope too, so its `/x` can sit beside an outer `/x` and runs when the component renders its children. The wrapped public define value (and its helper) is emitted only when something reads it as a value, so a define that is only called directly no longer leaves an unused binding under `noUnusedLocals`. The body of a direct `<define>` call is a `/var` scope too. A define that is read only by `<return>` or by a prelude statement keeps its public binding, a define with attributes that is only called directly no longer leaves an unused one, and a define param defaulting to `null` or `undefined` is typed `any`. A define read through a spread (`...Row`) keeps its public binding. A region lifts a `<define>` out of an imported tag's or a `<define>` call's body unless the body declares a `/var`, and a lifted define's name is unique across every scope of the region. The typeCheck projection calls a define through its public name. A direct call of a define whose name a param also binds (a `<for>` or define param) calls the authored name, so it reaches the local. A define with a non-ASCII name keeps its public binding. An untyped define param is typed `any`, except a plain name with a primitive default (`n = 1`), which keeps the type TypeScript infers from it. A region refuses a define lifted out of a tag body that declares tag params, and a region `/var` clashes by name with a define lifted from a tag body (`Duplicate declaration`). A param default holding a regex or template literal makes the call route by the authored name instead of dropping a shadowing binding. A `.preact.mx`/`.react.mx` region compiled for the TypeScript plugin projects defines by their public names, as the whole-file projection does, so a hover and `noUnusedLocals` never name `__mxDef_<name>`. The public define keeps its `length` as well as its `name`. `HostRegionInput.typeCheck` (core) and `RegionCompileOptions.typeCheck` (targets) are a new tooling-only option: the TypeScript plugin sets it so a region is projected the way a whole file is, with a direct define call typed and mapped by the define's own name while the private function still runs, so an argument arrives as written. A param default holding a comment, regex or template literal fails safe to the authored name.
