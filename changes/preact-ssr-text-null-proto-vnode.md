kind: Fixed

On Preact, a `${expr}` placeholder whose value is data from outside the template can no longer be read as markup by the server renderer. `<p>${input.x}</p>` with `input.x` set to a null-prototype object that has the fields of a vnode (`type`, `props`, `key`, `ref`; a decoder such as `qs` with `plainObjects` builds these) used to render `<p><img src="x" onerror="alert(1)"></p>` on the server, while the browser rendered `<p></p>`, so hydration disagreed with the server HTML; the same went for an array holding one, and for a placeholder that is the only child of an `<if>`, a `<for>` row or a body. Such data now renders nothing on the server, as it already did in the browser, and a plain object still renders nothing, as before. Strings, numbers, vnodes (`h()`, the jsx runtime, `Fragment`, `cloneElement`, a component's return value), class instances and arrays of them are unchanged. Each non-literal placeholder is now passed through the `__mxRenderable` check the dynamic tag already uses, so the generated code gains that call and one hoisted helper. A vnode is told apart by its own `constructor: undefined`, which JSON cannot carry; data decoded by a library that keeps `undefined` (`devalue`, `superjson`, `structuredClone`) can imitate one and must not reach a text placeholder. The shared emitter gained an internal `textDataGuard` dialect flag that only Preact sets, so only the hoisted `__mxRenderable` helper text differs in React and Hono output (an object whose prototype is an array, which JSON can build through a `__proto__` key and `Object.assign`, no longer passes as a class instance; it used to reach a dynamic tag as a node and crash Preact hydration).
