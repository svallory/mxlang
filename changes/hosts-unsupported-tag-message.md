A tag a host does not support in embedded MX now gets one message on every host: "`<X>` is not supported in embedded MX on <Host>." Before, each host worded the refusal its own way ("`<let>` is Marko reactive state; …", "`<script>` is a Marko client-runtime tag; …", "`<let>` is reactive state and requires a runtime; …" in Astro, and Angular's `<return>` text). The host's existing advice follows as a second sentence when there is one, for example "`<let>` is not supported in embedded MX on Preact. Use Preact's `useState` via `<const/x=useState(0)/>` or in the surrounding module." `<effect>` gets the first sentence alone on every host, with no `<script>` pointer. The code stays `MX_UNSUPPORTED_CONSTRUCT` and the position stays at the tag. Angular's and Astro's `<return>` refusals and Angular's `<try>` fallback in the emitter had no code before; they now carry `MX_UNSUPPORTED_CONSTRUCT`, and `<return>` is positioned at the returned value. This covers every tag the Preact, React, Hono, Solid, Angular and Astro hosts refuse, in whole files and in region files, plus Angular's and Astro's `<return>`; `client` and `server` blocks, `<else>` and `<else-if>` without an `<if>`, and refusals that are not about a tag (dynamic tag names, tag params, type arguments, tag variables) keep their texts. Core adds a third tag disposition, `{ kind: "unsupported", hint? }`, which core words with the new host declaration `hostName` (the display name), and the exported `unsupportedTagMessage(ctx, tag, hint?)` for a refusal a host raises itself after lowering (both `@unstable`). A disposition of kind `error` keeps working with its own `reason`. Tooling that matched the old texts (goldens, expected-error files) needs the new text.
