Messages a template author can see on Solid, Angular, Astro and the html target no longer name MX or Marko. A `client` block "holds code that runs only in the browser" (Solid, Angular); Solid's `<html-comment>` refusal "cannot render <!--…-->"; the `on:` fix-it says "`on:click=fn` is not an event binding" on Angular, Astro and html, and Solid's "was removed in Solid 2" drops "(Marko rejects this form too)"; `:=` "is a two-way binding" (Solid, Angular); Angular's `class:`/`style:` modifier "is not supported in an Angular template" and its `<const>` pattern-key refusal drops "as in Marko"; Astro's directive-named attribute "cannot be preserved as a plain attribute"; html's `<await>` refusal drops the sentence about Marko and its strict `<script>` refusal reads "`<script>` runs client code and requires a runtime". The run-time errors of the dynamic-tag helper that Preact, React and Hono print into their output, and Solid's own copy, drop the "MX: " prefix ("tag params |…| cannot be passed to a native element: …", "this value is a data attribute tag …"). The marker on a TypeScript diagnostic in generated code, in mx-tsc and the tsserver plugin, now reads " (in generated code, not yours: an internal bug; generated L:C)". Error codes, positions and severities are unchanged.
