A read of a tag variable that two or more nested bodies declare, with no binding of that name around the read, is now a compile error at the read on every host, as in stock Marko: `` Ambiguous reference, variable was defined in multiple places and was not shadowed. `` (`MX_INVALID_TAG_VAR`). It covers every tag-variable kind (an element reference such as `<div><div/el/></div><div><div/el/></div><button onClick() { el() }>c</button>`, `<const>`, `<let>`, `<id>`, a call's `/var`, a `<define>` name) at these read sites: an expression, an inert tag's value, a tag-param default, a `<script>` body, and a tag's type arguments and type parameters. A name in a TypeScript type position other than a `: T` annotation (`x as T`, `x satisfies T`, `f<T>()`, `<T extends U>`, `type A = T`) is a read too, as in stock, in a build that strips the types as in a compile that keeps them. Before, html, Preact, React and Hono emitted an unbound name that threw a `ReferenceError` when it ran, Solid bound the read to the first body's declaration, and a two-body call `/var` read got "is not in scope here". A read inside a body that declares the name, a read with a single nested declaration, and a name bound by an import, a tag param, the expression itself, `input` or a builtin global (`Map`) still compile.
