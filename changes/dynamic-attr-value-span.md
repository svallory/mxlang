A dynamic, bound, event or spread attribute in the IR (`lowerSource`) has `valueSpan`, the value as written, wrapper included. The default lowering strips `(x)`, a concise `<T>x`, `x!`, `x as T` and `x satisfies T` to the plain `x`, so `value` and `value.span` cover only `x`; `valueSpan` covers the whole written value (`(x as T)`, nested wrappers and the comments between them too), and a wrapped value is `valueSpan` differing from `value.span`. A plain value has the two equal, a spread's starts after the `...`, and `valueSpan` is always present on a `SpannedIr` attribute of those kinds. `IR_VERSION` is now `5`. Also fixed: an attribute's `span` stopped at the operand for `x as T`, `x!` and `x satisfies T` (`title=List as any` ended at `List`), and for a wrapper over a string literal; it now ends where the written value ends, so a diagnostic that reads it (a duplicate-attribute warning, a contract error on the value) ends after the whole attribute. A static attribute keeps `valueSpan` on its literal: a wrapper such as `("s" as const)` does not show in it, only as the attribute's `span` ending after `valueSpan`. Emitted code is unchanged.
