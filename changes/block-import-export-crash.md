An `import` or an `export` written inside a `static`, `server` or `client` block no longer fails to compile. `static { import x from "./x" }` used to be refused with `'import' and 'export' may only appear at the top level.` (the block's braces reached the statement check), and `server { export default foo }` crashed the compiler with an internal `undefined is not an object` error. The block's statements are now module-level statements, as in Marko: `static { import x from "./x"; export const z = 1 }` hoists both to the module, exactly as `static import x from "./x"` and `static export const z = 1` do, and in a `client` block the names they bind are declared as `var name;`. An `import` or `export` below the block's own statements (inside a nested block, an `if` or a function body, or in a second block) is still refused with the same message, now at the position of the declaration, and a real syntax error, decorator or JSX beside an import in a block is reported at its own position instead of as the import's placement error. Blocks without an `import` or `export` compile as before.
