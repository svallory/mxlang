---
packages: [core]
kind: Changed
---
Members leave core, and core reads no mark from a dialect's nodes any more. This is breaking for a dialect that has members (Mesh's `&name`): a member is now a node type the dialect registers itself, as an atom is. `IR_VERSION` is `7`.

- Removed: the `Member` and `MxMemberMark` types, a static `Attr`'s `member` field, the `ContractMember` type (and the `mx:Member` value in a `LoweredUnit` view), the contract attribute type `"member"` and its check, the `{ kind: "member", name, span? }` value of a trigger hook's `ctx.attribute`, core's reading of `extra.mxMember`, the member check that read it (`one member per slot`), and the 0.1.0-alpha.33 promise that marks survive until alpha.34. Core sets and reads no `extra.mxAtom` or `extra.mxMember`.
- Changed: a contract slot that declares `type: "member"` is a registration error that names the fix (declare a node type the file's dialect registers). A member is a node of a registered type: in an expression an entry of `Expr.nodes` whose forward is the expression its type's `lower` returned; as a whole value the node placed with `ctx.attribute(name, { type: "<id>:Member", name, span })`, a `static` attribute with the node on `Attr.node`. A value that is exactly one member (`on:load=&visible`) is a dynamic attribute whose `Expr.nodes` lists it. A slot `type: "<id>:Member"` accepts the node in both places and refuses a string, number, array, function or a node of another type, as any node-type slot does; an identifier, call or member expression has no knowable type and passes, so a slot that must refuse an expression around a member is the dialect's own check in `afterLower`.
- Changed: one member per name slot is no longer core's. Ask for it where the member is placed, with the existing `once` option of `ctx.attribute`: a second attribute of that name on the tag is refused at the later one, with the dialect's message (`{written}` and `{first}` fill in the later attribute and the earlier one's `line:column`). It differs from the old check in three ways Mesh must account for: the diagnostic code is `MX_INVALID_TRIGGER_USE` (it was `MX_INVALID_ATTRIBUTE`, so Mesh's mapping to `MESH_INVALID_OPTION` has to follow), the message is the dialect's own (the old one named the first member, ``one member per slot: `member` already holds `c`…``), and a written attribute of the same name after a member (`sort &d member=x`) is refused at that attribute, where it used to be a duplicate warning. `afterLower` cannot do it: core drops the earlier of two same-named attributes before the dialect sees them.
- Changed: a `type: "<id>:Member"` slot refuses a string, number, array, function or a node of another type, but, like any node-type slot, passes an expression with no knowable type (`load=(a.b)`, `load=(&visible && x)`). The old `"member"` slot refused those. Mesh keeps that refusal in `afterLower`: for each call attribute whose contract `type` is `mesh:Member` and whose value `type` is `mx:Expression`, accept it only when `value.nodes` holds exactly one `mesh:Member` node whose `forward === value.node`, and otherwise `unit.fail` with the message and `at: value.span` (the fixture `member-fixture.ts` has the code). `load=&visible` and `load=(&visible as any)` still pass.
- Migration (Mesh): register `mesh:Member` in `nodeTypes`: `Member: { keys: [], schema: { fields: { name: "data" }, slot: ["expression", "value"] }, parse: (text) => ({ name: text.slice(1) }), print: (node) => `&${node.name}`, lower }`, where `lower` returns `ctx.expression({ type: "MemberExpression", object: { type: "Identifier", name: "self" }, property: { type: "Identifier", name: node.name }, computed: false })` when `ctx.position === "expression"` and `ctx.expression({ type: "StringLiteral", value: node.name, extra: { raw: JSON.stringify(node.name), rawValue: node.name } })` otherwise, a fresh object on each call. Name it from the expression list with `{ ...MEMBER, node: { type: "Member", dialect: "mesh" } }`; the attribute and line lists keep the `{ call: "member" }` row, whose `lowerTrigger` returns `ctx.attribute("member", { type: "mesh:Member", name, span }, { once })` in an attribute list. Contract slots: `member()` becomes `{ type: "mesh:Member" }` and a list of members `{ type: "array", items: "mesh:Member" }`. Readers: replace each read of `extra.mxMember` (`tree.ts`, `contracts.ts`, `expression.ts`) with `Expr.nodes` (`expr.nodes.find((n) => n.forward === babelNode)`) and each read of `Attr.member` with `attr.node?.type === "mesh:Member"`. Stop setting `extra.mxAtom` on `mesh:Atom`'s forward. For `%.now` and `%.today` core never read `extra.mxTransaction`, so nothing breaks; to leave the mark behind, register `mesh:Transaction` with `schema: { fields: { name: "data" }, slot: ["expression"] }` (`parse: (text) => ({ name: text.slice(2) })`, `lower` returning the `%`-rooted `MemberExpression` as a fresh object) and name it from the `transaction` expression row as `{ ...TRANSACTION, node: { type: "Transaction", dialect: "mesh" } }`.
