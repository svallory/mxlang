The body of a tag that resolves to a host component now reaches the component exactly as hand-written JSX would pass it. `import { Fragment } from "hono/jsx"` then `<Fragment>${input.count}</Fragment>` used to wrap the body in a fragment of MX's own with a `{null}` sibling, so a component received a fragment element instead of its children, and on Hono a `Fragment` rendered `0` where `<Fragment>{0}</Fragment>`, written by hand, renders nothing. The `content` function the emitter writes for such a call now returns what `<Tag>…</Tag>` would pass as `children`: the bare value for a lone placeholder, the string for text, the element for an element and the array of children for several, and the render prop of a call with tag params returns its body the way `(n) => n` does. A binding imported from a module that is not an MX or Marko template, or a local whose value cannot be proven, is a host component; MX's own fragments (an `<if>` branch, a `<for>` row, a define call, a dynamic tag written as `<${expr}>`, a positional call and an attribute-tag body) keep their `{null}` sibling. A dynamic tag whose binding is absent at run time still renders its body on its own, now through a closed fragment, so a lone `0` still renders on Hono.
