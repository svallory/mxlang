As in Marko, a native element now refuses the attribute names of other frameworks' template syntax unless the target host's framework gives the name a meaning there: `MX_INVALID_ATTRIBUTE` at the attribute, with stock Marko 6.4.4's message and hint (`` `ref` is not a valid attribute, did you mean `<tag/ref>`? ``). The names are `className`/`classList` (`class`), `htmlFor` (`for`), `acceptCharset` (`accept-charset`), `httpEquiv` (`http-equiv`), `defaultValue` (`value`), `defaultChecked` (`checked`), `key` (`<for by>`), `ref` (`<tag/ref>`), `v-if`/`v-show` (`<if>`), `v-else` (`<else>`), `v-else-if` (`<else if>`), `v-for` (`<for>`), `v-model` (`value:=state`), `v-bind` (`...attrs`), `v-html` (`$!{html}`), `v-text` (`${text}`), and the colon forms `v-on:x` (`onX`), `bind:x` and `v-model:x` (`x:=state`), `v-bind:x` (`x`); a bound `x:=` or a method `x(){}` keeps the name. What changes per host: React and Preact start refusing `classList` and the `v-*`/`bind:` names; Hono also refuses `acceptCharset`, `defaultValue` and `defaultChecked`; Solid refuses every name but `ref`; html, Angular and Astro refuse every name. The same check now runs on a dynamic tag whose name is a string literal with no placeholder (`<${"div"} key=1/>`, whatever it names) and on html's claimed `<html-script>`/`<html-style>`. Spread keys, a component's input, other dynamic tags and other spellings (`classname`, `Ref`, `ref:x`) are unaffected. A host lists the names it keeps in `HostDeclarations.acceptsReservedAttrNames`.
