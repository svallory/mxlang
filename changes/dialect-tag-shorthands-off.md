`tagShorthands` (`@unstable`), a boolean field of the syntax table, default `true`, for a dialect whose tag names are JSX member names. With `false` in a dialect's `table`, the tag head has no `#id` and `.class` shorthands and no implicit `div`: a `.` continues the tag name, so `billing.InvoiceVoided` is one tag in concise and HTML form alike (a wildcard `children["*"]` entry matches it, and `</billing.InvoiceVoided>` closes it). A `#` anywhere in a tag head, and a head that starts with `.` or `#`, is the new code `MX_NO_TAG_SHORTHAND` (listed in `MX_DIAGNOSTIC_CODES`), positioned at that character; a trailing `.`, a doubled `..` and a `.` right after a `${…}` are `MX_INVALID_TAG_NAME`, positioned at the dots. The field is validated (a non-boolean is `` `tagShorthands` is a boolean ``) and part of `syntaxHash`, so a table with `false` never shares a parse with one with `true`. The default row now states `tagShorthands: true`, which changes the default table's hash and no file's parse: every `.mx` file reads and compiles as before. In the parser, the two codes are template errors named `MX_NO_TAG_SHORTHAND` and `MX_INVALID_TAG_NAME` (`MxParseError.code`, and the `MxErrorCode` union of `@mxlang/babel`).
