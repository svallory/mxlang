As in Marko, a tag variable named `input` in a template's top-level body is now refused on every host: `<const/input=…>`, `<let/input=…>`, `<define/input>`, `<id/input>`, a tag call's `/input`, a dynamic tag's `/input`, and on html, Preact and React an element reference (`<div/input/>`) are `MX_DUPLICATE_DECLARATION` at the name: "Duplicate declaration of `input`: it is already the template's input. Rename the tag variable." Before, Preact, React and Hono emitted a module that declared `input` twice, html emitted its throwing element-reference getter beside the `input` parameter, Angular accepted a top-level `<const/input=…>`, and html's own `<let>`/`<const>` message is replaced by this one at the top level. A tag param named `input` (`<for|input|>`) and a tag variable `input` inside an `<if>`, `<for>` or `<define>` body still compile. On Preact and React a string or bare `ref` beside an element reference (`<div/el ref="x"/>`, `<div/el ref/>`) is now a compile error at the `ref` attribute instead of a second `ref` prop: neither framework has string refs; `ref=myRef` (a function or a ref object) is still handed the node. `el()` on `<html-script/el>` and `<html-style/el>` is now typed `HTMLScriptElement` and `HTMLStyleElement`, the elements emitted, so `el().async` and `el().media` type-check.
