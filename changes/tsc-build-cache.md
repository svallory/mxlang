`mx-tsc -b` caches the Angular template pass per project of the build graph, in a sidecar file beside the project's build info (`<tsbuildinfo>.mx-ng.json`). A project's stored template diagnostics are replayed, with no extra program and no Angular checker, only when a SHA-256 key over every input of that answer is unchanged: the build info's per-file hashes, the tsconfig and its `extends` chain, the `.mx` files' text, every `package.json` and MX config file that decides their host and Angular config (or its absence), the custom-tag directories and files their tag discovery reads, the `@angular/compiler-cli` and TypeScript the checker resolves, mx-tsc's own code, that of its MX externals (core with its parse layer, the element table) and the `@angular/compiler` version, and the projects before it in build order. A no-change second `-b` run is again close to `tsc -b`'s own speed. `-b --force` bypasses and rewrites the stored answers. Nothing is stored for a project whose pass printed an MX compile, host-policy or ambient-types diagnostic or could not check its templates, for a run whose TypeScript pass failed, or for a project without an incremental build info (a non-composite project), for a project with an MX config module (`mx.config.ts` and the like, whose imports are not inputs), or for one holding a file kind the key does not cover (a dialect's file); those keep running the full pass. Watch mode is unchanged. The sidecar is written into the build info's directory, usually `outDir`: a package that publishes `outDir` excludes `*.mx-ng.json` from its `files`.
