A name exported twice across the module statements is now a compile error on every target. `static const q = 1`, `static export { q }` and `server export { q }` used to compile, and the module they made did not load (`SyntaxError: Duplicate export of 'q'`). The second export is refused at its name with `MX_DUPLICATE_DECLARATION`, and the message says where the first is: two export lists, an export list beside `export const`, `export function`, `export class`, `export enum`, `export namespace` or `export var`, `export { a as q }` beside `export { b as q }` or `export const q`, a re-export (`export { q } from "./m"`, `export * as q from "./m"`) beside any of them, and two names in one list, in a block or without one. A `server` export and a `client` export of one name stay legal, since each output keeps one side. So do type exports, `export declare` forms, `export * from` of two modules, function overloads with their implementation, an export list that names a type-only import or a namespace holding only types, and a namespace that merges into an earlier function, class, enum or namespace of its name, and an enum that merges into an earlier enum or into a namespace that is itself exported. To fix it, export each name once: rename one with `export { local as other }`, or remove it.
