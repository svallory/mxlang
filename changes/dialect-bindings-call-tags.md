A dialect can set `bindingsCallTags: false` so that no file-local binding (an `import`, a `<const>`, a `<define>`, a loop or define parameter) turns a capitalized tag into a component call in its files. The tag is then read as if unbound: its contract applies, a parent's wildcard `children["*"]` claims it, and the unknown-tag rules judge it, while the import stays in the file's imports. A data dialect can now import a value and name a tag after it; before, that failed with a dynamic-tag error. The default (`true`) is unchanged, and a non-boolean value fails the dialect at load. Two messages also name the tag now: a capitalized tag bound in a data file reports "`<Task>` is bound in this file, so it is a dynamic tag" with the two ways out, and a wildcard child refused for being bound says so; the wildcard rule reads "must not already be a tag" in place of "must be a name that is not already a tag". The exported `ChildNode` type's `known` field also admits `"bound"`.
