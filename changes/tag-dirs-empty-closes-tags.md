A dialect can now close MX's generic `tags/` directory to its own files with `tagDirs: []` in its `package.json#mx.dialect`. The manifest used to refuse an empty `tagDirs` with ``mx.dialect.tagDirs must be a non-empty array of the directory names the dialect's files discover tags in``, an error at the field that every file of the project then reported, so a dialect could not say "none". An empty array now means no directory at all: the dialect's files get no definition from `tags/`, and a call of a name defined there is an unknown tag under `unknownTags: "reject"`. An absent `tagDirs` still means `["tags"]`, as before, and `.mx` files in the same project still get `tags/`. `tagDirs` keeps its other errors at the key: a value that is not an array, an entry that is not a directory name, and a repeated entry. The message for a value that is not an array no longer says "non-empty": `` `mx.dialect.tagDirs` must be an array of the directory names the dialect's files discover tags in (`["components"]`), or `[]` for none ``. `mx.tags` and `mx.contracts` are not part of this: they stay governed by `mxConfigTags`, and `tagExtensions` and the `tagFile` hook are unaffected. When an MX file's scan meets a tag file that such a dialect claims in a directory it does not read, the `MX_MISPLACED_TAG_FILE` warning now ends `Mesh discovers no tag directories.` instead of `Mesh discovers tags in .`
