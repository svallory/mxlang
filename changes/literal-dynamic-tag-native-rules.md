A dynamic tag whose name is a string literal with no placeholder and does not name a native element (`<${"Foo"}>`, `<${"my-el"}>`, `<${"style"}>`) now keeps Marko's native-tag field rules on every host, with Marko's messages: tag arguments (`<${"Foo"}(1)/>`, "Tag does not support arguments.", `MX_UNSUPPORTED_TAG_ARGUMENTS`, at the arguments), tag params (`<${"Foo"}|x|>`, "Tag does not support parameters.", `MX_UNSUPPORTED_CONSTRUCT`, at the first param), attribute tags (`<${"Foo"}><@a/></>`, "Tag does not support nested attribute tags.", `MX_UNSUPPORTED_CONSTRUCT`, at the first one) and a destructured tag variable (`<${"Foo"}/{a}/>`, "Tag variables on native tags cannot be destructured.", `MX_INVALID_TAG_VAR`) are refused in core. Before, they compiled, except params, which only html, preact, react and hono refused (now reported at the first param instead of the tag; with arguments too, the arguments are reported first, as in Marko). An empty `()` or `||` writes nothing and compiles, as in Marko, so `<${"my-el"}||>x</>`, which html, preact, react and hono refused, now compiles on every host. An identifier tag variable, attribute values and computed names keep the dynamic tag's handling.
