`lowerSource` takes `stripTypes?: boolean`. The default (`true`) is unchanged: TypeScript is erased from the nodes before lowering, so a top-level `as`, `!`, `satisfies` or `<T>x` is replaced by its operand, and annotations are gone from the nodes (`Expr.code` is sliced from the source either way). `stripTypes: false` keeps the authored TypeScript in the nodes a dialect's `nodeType.lower`, contract hooks and `afterLower` see (`TSTypeAnnotation`, `returnType`, `TSAsExpression`, …). With `false`, a top-level assertion stays around the value, so an attribute whose value is an assertion over a literal (`a=("s" as const)`) is `dynamic` with shape `other` rather than `static`, `boolean`, `object`, `array` or `string`. Core's own checks look through the assertion, so a bound attribute (`v:=(y as any)`) and a contract's `type` check give the same result as the default. A tag-file hook's `ctx.lower` takes the option but does not inherit the outer call's value, and its memo is keyed on it.
