`lowerSource` takes `stripTypes?: boolean`. The default (`true`) is unchanged: TypeScript is erased from the nodes before lowering, so a top-level `as`, `!`, `satisfies`, `<T>x` or `x<T>` is replaced by its operand, and annotations are gone from the nodes (`Expr.code` is sliced from the source either way). `stripTypes: false` keeps the authored TypeScript in the nodes a dialect's `nodeType.lower`, contract hooks and `afterLower` see (`TSTypeAnnotation`, `returnType`, `TSAsExpression`, …). With `false`, an assertion stays around the value, so an attribute whose value is an assertion over a literal (`a=("s" as const)`) is `dynamic` with shape `other` rather than `static`, `boolean`, `object`, `array` or `string`, and a contract's `type: "expression"` check follows that kind (`a=("s" as const)` is refused by default and accepted with `false`). Every other check of core looks through TypeScript assertions (`as`, `satisfies`, `!`, `<T>x`, `x<T>`) and gives the default's diagnostics, positions included: the bound-attribute check (`v:=(y as any)`) and a contract's `string`, `number`, `boolean`, `enum`, `literalOnly`, `array`, `items`, `function`, `atom` and `member` checks. An attribute's `span` ends at the operand either way, so with `false` it does not contain the wider `span` of its value (`a=(1 as number)`: attribute [3,7), value [6,17)). A tag-file hook's `ctx.lower` takes the option but does not inherit the outer call's value, and its memo is keyed on it.
