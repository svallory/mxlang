**Breaking:** core has no name sugars. Every form reads as stock Marko reads it, with Marko's errors; a dialect that wants a name sugar claims it through its syntax table. The tag-adjacent shorthand (`<div#a.b>`, `<#a>`, `<.b>`) is unchanged. Readings that change, all visible to a dialect such as Mesh: a `:` in a tag head is part of the name (`<input:email>`, `<uuid:id>`, `<:x>` and concise `entity:Todo` are one tag name each, so on web an unknown custom tag; Angular's `<svg:rect>` passes through as written), and part of a shorthand part (`<div.c:b>` is the class `c:b`, `<div#d:b>` the id `d:b`); an attribute named `:x` is Marko's `value:x` and a bare `:` is `value:`, `:x(…)` is Marko's "Unsupported arguments on the `value:x` attribute."; a spaced `#x` or `.x` in attribute position is `Invalid attribute name` (a host with `acceptsForeignAttrNames`, Angular, keeps `#ref`); a spaced ` :x` or ` .x` after any value, a default value or a single atom included, continues the value as in stock, so `<div x=a :b/>` and `<if=:a :b>` are Marko's "Expected a single expression, but found `:` after it." and `x=a .b` is member access. Removed exports: `sugarTagName` (`@mxlang/core`), `HostDeclarations.claimsAttributeHash` (Angular no longer sets it), and the `":"` value of `MxShorthand.sigil` (`@mxlang/babel`). Removed codes: `MX_SUGAR_ARGUMENTS`, `MX_SUGAR_BOUND`, `MX_SUGAR_DYNAMIC`, `MX_SUGAR_NAME_INVALID`, `MX_SUGAR_NAME_MISSING`, `MX_SUGAR_ON_STATEMENT`, `MX_SECOND_NAME`, `MX_COLON_BEFORE_DYNAMIC` and `MX_SHORTHAND_INVALID`; the "`:x` right after a default value is not supported" error is gone with them. The `Attr.sugar` and `Attr.sugarValueOf` IR fields stay, set by the tag-adjacent shorthand and by a dialect's triggers.
