packages: [core]
kind: Changed
---

A custom tag's definition with an unknown tag-level key is now refused, wherever it comes from: a `customTags` entry, a `.tag.ts` sidecar, an `mx.contracts` entry, and a dialect's `contracts` entry (a sidecar in an `mx.tags` directory included), all through one check. `atributes: {...}` used to be dropped silently, leaving the tag with no attribute contract. It now fails with `` Unknown key "atributes" in the declaration of tag "x"; allowed: parseOptions, attributes, attributeTags, children, parents, defaultTag, analyze, transform, finalize, template `` (plus any key the file's syntax module claims through `contractFields`), the same wording as the attribute-level refusal. The list is what that source accepts: an `mx.contracts` entry lists `parseOptions, attributes, attributeTags, children, parents, defaultTag, analyze`, a dialect's `contracts` entry the same plus `transform, finalize`. The error is positioned at the key in a sidecar or an `mx.contracts` module (the file's `1:0` when the module does not write the entry as a literal); a `customTags` entry passed to the API has no position, so `lowerSource` reports it at the source's `1:0`. When an entry has several unknown keys, the first one in the order written is reported. A file that compiled before can now fail: rename the misspelt key (`attributes`, `children`, ...) or delete it, and a key you meant to keep must be claimed by the dialect's `contractFields`. A dialect's `contracts` entry used to read `` `contracts.card`: `atributes` is not a contract key (parseOptions, …, or a key the dialect claims in `contractFields.tag`) ``; it now reads `` `contracts.card`: Unknown key "atributes" in the declaration of tag "card"; allowed: parseOptions, attributes, attributeTags, children, parents, defaultTag, analyze, transform, finalize ``, with the same code and position. An unknown key in an `mx.contracts` entry used to be reported as `` `atributes` is not allowed in `mx.contracts`; use a tag sidecar … `` at the module's `1:0`; it now has the message above, at the key.
