kind: Changed

A `<script>` body that does not parse is now a compile error, `MX_INVALID_STATEMENT`, positioned at the syntax error, as in Marko. Before, the html target emitted none of the body and so accepted any text (`<script>@d class C {}</script>` and `<script>const = 1;</script>` compiled), and the check for a stale `<const>` read in a `<script>` body was switched off for such a body without a word. A decorator, JSX or a proposal syntax in a `<script>` body is refused with a message that says what to write instead (a `.ts` module for a decorated class, a tag for markup); any other error carries Babel's message at Babel's position. A body that parses compiles as before: an `import`, an `export`, a top-level `return` or `await`, type annotations, `enum`, `satisfies`, `namespace` and `declare` are accepted, and a body that holds a `${…}` placeholder is still not read. On a host that refuses `<script>` (Preact, React, Hono, Solid, Angular, Astro), a body that does not parse is now reported at its syntax error before the host's "`<script>` is not supported" message.
