The type-check of a `.mx` file now types a `client` name the way the server render sees it: as `undefined`, and not exported. `client let q = 1` with `<div>${q.toFixed(2)}</div>` used to check clean and throw on the server render; it now reports `'q' is possibly 'undefined'` at the read, and a client function or class called in the template is an error too. `import { x } from "./ca.mx"` of a `client export const x` used to pass silently; it now reports TS2614 at the specifier, for a plain, a `static` and a `server` import and for a `.ts` importer, and a `server` or `static` export of the same file stays importable. Inside client code (a handler, a `client` block, a later `client` statement) a client name keeps its declared type, and hover, completions and error positions there are unchanged; a top-level `return` in a `client` block is still reported (TS1108) at the `return`. In the generated TypeScript for tooling, a `client` statement's names are declared `var q: undefined` at module level and its code runs in a function the module calls where the last `client` statement stands, so a use before declaration is still reported; the module that runs is unchanged. Known limits: a `client import` of another module's client export reports TS2614, because the type-check reads that module as the server sees it. A client interface or type alias that names a client value (a class, an enum, a `const` through `typeof`) is checked in the client scope, so a type outside it, such as the page's own `export interface Input`, cannot name that class or enum, and `import type` of such a type from another file does not find it; a client type that names no client value stays at module level and importable. A client `namespace` is declared at module level, where a client value is `undefined`, so a namespace body that reads one reports it. A `client` statement that reads a `static` or `server` name declared after it, but before a later `client` statement, is not reported as used before its declaration. From a template read of a client name, go-to-definition lands on the read, and rename or find-references on the declaration do not include it.
