The type-check of a `.mx` file now types a `client` name the way the server render sees it: as `undefined`, and not exported. `client let q = 1` with `<div>${q.toFixed(2)}</div>` used to check clean and throw on the server render; it now reports `'q' is possibly 'undefined'` at the read, and a client function or class called in the template is an error too. `import { x } from "./ca.mx"` of a `client export const x` used to pass silently; it now reports TS2614 at the specifier, for a plain, a `static` and a `server` import and for a `.ts` importer, and a `server` or `static` export of the same file stays importable. Inside client code (a handler, a `client` block, a later `client` statement) a client name keeps its declared type, and hover, completions and error positions there are unchanged; a top-level `return` in a `client` block is still reported (TS1108) at the `return`. In the generated TypeScript for tooling, a `client` statement's names are declared `var q: undefined` at module level and its code lives in a function nothing calls; the module that runs is unchanged. Known limit: a `client import` of another module's client export reports TS2614, because the type-check reads that module as the server sees it.
