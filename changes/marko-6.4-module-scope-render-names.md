Module level code that names something that exists only while the template renders is now a compile error, as in Marko 6.4: a `static`, `server` or `client` block (including the statements of a `static { … }` block) or an `export` statement that references a tag variable (`<let>`, `<const>`, `<define>`, declared anywhere in the file), `input`, `$global` or `$signal`. The error is `MX_RENDER_ONLY_IN_MODULE`, positioned at the name with its end: "`count` exists only while the template renders, so module level code (`static`, `server`, `client` and `export` statements), which runs once as the template loads, cannot reference it. Reference it in the template instead, passing it to module level functions as an argument." It is raised by core, so every host and `lowerSource` report it the same way, where these references used to compile to code that read an unbound name. A module level declaration with the spelling of a tag variable in the template's top level (`static count = 1` beside `<let/count=0/>`) is refused at the declaration. A parameter or local of a module function that shadows the name, a property name, a name in a type position, a tag param (`<for|item|>`) and a module binding that shares the spelling of a tag variable only a nested tag declares are not errors. A host that refuses `server` or `client` still reports that refusal first, and the `none` tag rules leave a dialect's statements alone. Move the value into the template and pass it to a module level function as an argument.
