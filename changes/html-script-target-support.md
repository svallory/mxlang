`<html-script>` now writes a real `<script>` element on every host, with its attributes and a body that is script text, as stock Marko 6.4.4 does. The html target (`@mxlang/target-html`) dropped every attribute (`<html-script type="module" src="/a.js">` printed a bare `<script>`) and HTML-escaped the body, so `a && b` reached the browser as `a &amp;&amp; b`; it now keeps the attributes (spreads, dynamic values and `nonce=` included, with the shared element rules) and writes the body as Marko does: each `${…}` stringified as in any text, then the joined body escaped for script context (`<script`, `</script` in any case and `<!--` become `\u003C…`), so no value can close the element. Preact, React, Hono and Solid printed a literal `<html-script>` element: they now print `<script>`, with the body through the renderer's raw-HTML prop (`dangerouslySetInnerHTML`, Solid's `innerHTML`) because a JSX renderer HTML-escapes a text child. Astro printed a literal `<html-script>` too: it now prints `<script is:inline … set:html={…}>`, `is:inline` so Astro keeps the element where it is instead of bundling it. Angular's template compiler removes every `<script>` element, so that host now refuses `<html-script>` at the tag with the ways Angular loads a script (`index.html`, the `scripts` array of `angular.json`, the DOM API) instead of emitting an element ngtsc rejects. No host invents a `nonce`: Marko reads one from `$global.cspNonce`, which an MX render does not have, so the author's own `nonce=` is the only source. On Preact, React and Hono a whole-file body is still read as markup: an element, an `<if>` or a comment in it is refused with an error (it would otherwise be silently dropped from the script, so write markup-like text inside a string placeholder), and a body loses its leading and trailing whitespace, because their whole-file compile does not register the raw-text parse option of `<html-script>`; the html target, Solid and Astro keep both, as Marko does.
