In an Angular tag, a template that reads a name its own module declares (`static let n`, `static const k`, a `static function f`, or an imported value) now sees it. The generated component class had no such member, so `{{ n }}` rendered blank, or failed `ng build` under strict template checks, and MX reported nothing. The class now exposes each module-level name the template reads through an accessor, so a `static let` that module code reassigns shows its current value, and a `let` or `var` also takes an assignment from the template. A type-only name gets no member. A name the template binds itself (`<for|n|>`, `<const/n=…/>`) keeps meaning that binding. When a module name is also an `Input` property, or is a name Angular gives a meaning on a class (`constructor`, `ngOnInit`, …), the template reads the module's value through a generated `__mxModule_<name>` member, so a valid program compiles. A `var` declared inside a `static { }` block is bound too. A `const enum` read is a positioned error at the read, because it has no run-time value: the message says to drop `const`.
